# 00. 개요

- 상태: 초안
- 작성일: 2026-11-16

## 1. 목표

Quire는 브라우저에서 동작하는 **페이지 기반 문서 에디터 엔진**이다.
Word·한글(HWP) 수준의 조판 품질과 Google Docs 수준의 실시간 협업을 동시에 목표로 한다.

기존 웹 에디터가 `contenteditable` + DOM 흐름 레이아웃 + 엄격한 트리 모델이라는 공통 기반 때문에
해결할 수 없었던 아래 9가지 한계를 **모두** 해결 대상으로 삼는다.

| # | 해결 대상 | 기존 구조의 원인 | Quire의 해법 | 관련 문서 |
|---|---|---|---|---|
| L1 | 진짜 페이지 레이아웃 (쪽 나눔, 머리말·꼬리말, 쪽 하단 각주, 표 분할, 다단) | DOM은 연속 흐름 레이아웃 | 자체 레이아웃 엔진의 페이지 조립 단계 | 02 |
| L2 | 어울림 배치, 글상자, 절대 위치 개체 | CSS float 한계, 편집과 불일치 | 레이아웃 엔진의 배제 영역(exclusion) 계산 | 02 |
| L3 | 입력·IME 완전 제어 | 입력을 브라우저가 소유 | 숨긴 입력 요소 + EditContext, 자체 조합 상태 머신 | 03 |
| L4 | 다중 커서, 사각형 선택, 블록·텍스트 혼합 선택 | DOM Selection은 단일 범위 | 자체 선택 모델 | 03 |
| L5 | 초대형 문서 (수천 쪽) | 전체 문서가 DOM에 존재 | 증분 레이아웃 + 보이는 쪽만 렌더링 | 02, 04 |
| L6 | 구조 변경까지 포함한 변경 추적 | 변경 추적이 마크로 덧붙여짐 | 연산 기반 이력 + 문단 경계 표식 | 01, 05 |
| L7 | 블록 경계를 넘어 겹치는 주석·범위 | 트리 모델에서 마크가 쪼개짐 | 구조와 분리된 범위 레이어 | 01 |
| L8 | 협업 중 블록 이동, 사용자별 실행 취소 | 이동이 삭제+삽입, CRDT가 후속 부착 | 이동을 1급 연산으로, CRDT 전제 설계 | 01, 05 |
| L9 | 정밀 조판 (한글 줄바꿈, 금칙, 양쪽 정렬, 장평·자간) | 브라우저 텍스트 렌더러 의존 | HarfBuzz 셰이핑 + 자체 줄바꿈 | 02 |

## 2. 비목표 (당분간)

- 세로쓰기, 루비 문자
- 오른쪽에서 왼쪽으로 쓰는 문자(RTL)의 완전 지원. 단, 데이터 모델과 레이아웃 인터페이스는 bidi를 막지 않게 설계한다
- 스프레드시트·프레젠테이션 편집
- 기존 포맷(DOCX, HWPX)의 100% 충실한 왕복 변환. 가져오기·내보내기는 "주요 요소 보존"을 목표로 한다

## 3. 설계 원칙

1. **렌더링과 문서 의미의 분리.** 문서 모델은 화면을 모르고, 레이아웃 엔진은 DOM을 모른다.
2. **레이아웃 엔진은 순수 계산 모듈.** 같은 입력(문서, 글꼴, 엔진 버전)이면 어느 기기에서든 같은 쪽 나눔 결과를 낸다. Web Worker와 Node에서 실행 가능해야 한다.
3. **모든 변경은 연산(operation)이다.** 실행 취소, 협업 동기화, 변경 추적, 버전 비교가 하나의 연산 이력을 공유한다.
4. **위치는 인덱스가 아니라 ID로 고정한다.** 동시 편집과 주석 고정이 이 위에서 동작한다.
5. **캔버스를 쓰면서 잃는 것은 전부 직접 되찾는다.** 접근성, 찾기, 맞춤법, 클립보드를 1급 요구사항으로 취급한다. 특히 접근성은 1단계부터 함께 만든다.
6. **한글을 기본값으로 설계한다.** IME, 줄바꿈, 금칙, 글꼴 대체는 부가 기능이 아니라 기본 동작이다.

## 4. 전체 아키텍처

```
┌──────────────────────────────────────────────────────────┐
│  기능 플러그인 (서식, 표, 수식, 댓글, AI …)                 │
├──────────────────────────────────────────────────────────┤
│  명령 계층: Command → Transaction(Operation[])             │
├────────────────────────┬─────────────────────────────────┤
│  입력 층 (03)           │  선택 모델 (03)                   │
│  숨긴 입력 / EditContext │  다중 범위, 사각형, 블록 선택       │
├────────────────────────┴─────────────────────────────────┤
│  문서 모델 (01) + 범위 레이어 + 연산 로그 (05)              │
│  └ 동기화 어댑터 (CRDT) / 실행 취소 / 변경 추적 / 버전       │
├──────────────────────────────────────────────────────────┤
│  레이아웃 엔진 (02): 아이템화 → 셰이핑 → 줄바꿈 → 쪽 조립   │
│  출력: 레이아웃 트리 (Page > Region > Line > Run > Glyph)    │
├─────────────────────────────┬────────────────────────────┤
│  캔버스 렌더러 (04)           │  접근성 미러 DOM (04)        │
│  보이는 쪽만, 오버레이 분리    │  스크린리더, 찾기, 맞춤법     │
└─────────────────────────────┴────────────────────────────┘
```

### 데이터 흐름 (키 입력 1회)

1. 입력 층이 키·조합 이벤트를 받아 **명령**으로 변환한다 (`insertText("가")`).
2. 명령이 현재 선택 상태를 보고 **트랜잭션**(연산 목록 + 전후 선택)을 만든다.
3. 문서 모델에 트랜잭션을 적용하고, 변경된 문단 ID 집합(dirty set)을 낸다.
4. 레이아웃 엔진이 dirty 문단만 다시 셰이핑·줄바꿈하고, 첫 영향 쪽부터 쪽 조립을 다시 하다가 이전 결과와 쪽 경계가 수렴하면 멈춘다.
5. 렌더러가 화면에 보이는 쪽 중 바뀐 것만 다시 그린다. 접근성 미러를 갱신한다.
6. 동기화 어댑터가 연산을 원격 피어에 보낸다.

목표: 1,000쪽 문서에서 1~5 전체가 **16ms 이내** (06 성능 목표 참고).

## 5. 패키지 구성 (예정)

모노레포, TypeScript. 레이아웃 핫스팟은 이후 Rust→WASM 이식 후보.

| 패키지 | 역할 | DOM 의존 |
|---|---|---|
| `@quire/model` | 문서 모델, 위치, 범위, 연산, 스키마 | 없음 |
| `@quire/sync` | CRDT 어댑터, 실행 취소, 변경 추적, 버전 | 없음 |
| `@quire/text` | 글꼴 로드, HarfBuzz 셰이핑, 줄바꿈 규칙 | 없음 (WASM) |
| `@quire/layout` | 문단 레이아웃, 쪽 조립, 레이아웃 트리 | 없음 |
| `@quire/view` | 캔버스 렌더러, 입력 층, 선택, 접근성 미러 | 있음 |
| `@quire/commands` | 편집 명령, 키맵 | 없음 |
| `@quire/editor` | 위를 묶은 공개 API | 있음 |
| `apps/playground` | 개발·검증용 앱 | 있음 |
