# 05. 협업과 이력

- 상태: 설계 (1–6단계에서 구현함. 구현하며 바뀐 점과 결과는 09–16의 결과 절에 있다)
- 해결 대상: L6, L7, L8
- 구현 계획: 동기화·사용자별 실행 취소·저장은 09, 주석·댓글·변경 추적·버전·권한은 [14](14-collaboration-history.md)

## 1. 요구사항

- R1. 여러 사용자가 동시에 편집하고, 네트워크가 끊겼다 다시 연결되어도 모든 피어가 같은 문서로 수렴한다.
- R2. 문단 분할·병합, 블록 이동, 표 구조 변경이 동시 편집과 함께 일어나도 다른 사용자의 입력을 잃거나 중복하지 않는다.
- R3. 실행 취소는 **내 변경만** 되돌린다. 다른 사용자의 변경 위에서도 의도대로 동작한다.
- R4. 변경 추적(제안 모드)은 텍스트뿐 아니라 문단 분할·병합, 서식, 표 구조, 블록 이동을 제안으로 기록하고 수락·거부할 수 있다.
- R5. 임의 시점의 버전을 보고, 두 버전을 비교하고, 복원할 수 있다.

## 2. 동기화 모델

- 문서 모델(01)의 상태는 **CRDT**로 저장한다. 서버는 업데이트를 중계·저장할 뿐 변환(OT)하지 않는다. 오프라인 편집이 기본으로 지원된다.
- 01의 연산은 CRDT 업데이트로 변환되는 **상위 의미 계층**이다. 에디터 코드는 CRDT API를 직접 부르지 않고 `@quire/sync` 어댑터를 통한다. CRDT 구현을 바꿀 수 있게 하기 위함이다 (ADR-0003).

| 모델 요소 | CRDT 표현 |
|---|---|
| 스토리의 원소 열 (`¶` 포함) | 시퀀스 CRDT (텍스트) + 서식 구간 (Peritext 방식) |
| `¶`, `§`, 개체 속성 | 원소 ID로 키를 둔 맵 (LWW 레지스터) |
| 스토리 목록, 스타일, 구역 | 맵 |
| 주석 레이어 | 주석 ID → {시작 위치, 끝 위치, 데이터} 맵 |

### 프레즌스 (영속하지 않음)

- 원격 커서·선택, 사용자 이름·색, 조합 중 상태(선택 사항, 03 O-9)는 별도 프레즌스 채널로 전송한다. 위치는 ID 기반 `Position`이라 상대 문서 상태와 무관하게 해석된다.

## 3. 블록 이동 (L8의 핵심 난제)

평평한 원소 열(01 §2)에서 블록 이동은 "구간 이동"이다. 일반 시퀀스 CRDT는 이동을 지원하지 않거나 단일 원소 이동만 지원한다.
삭제+삽입으로 처리하면 생기는 문제:

- A가 문단 P를 이동하는 동안 B가 P를 편집 → B의 편집이 삭제된 원본(묘비)에 들어가 유실
- A와 B가 동시에 P를 다른 곳으로 이동 → P가 두 곳에 복제

후보 해법:

| 안 | 방식 | 장점 | 단점 |
|---|---|---|---|
| M1 | 삭제+삽입 + **이동 포워딩**: 이동된 원소마다 "이동 후 ID" 매핑을 기록. 원본 묘비에 도착한 편집을 이동 후 위치로 다시 적용. 동시 이동은 결정적 규칙(예: 최신 Lamport 시각 우승)으로 하나만 살림 | 일반 시퀀스 CRDT 위에 구현 가능 | 포워딩 규칙이 복잡하고 모든 피어에서 같은 결과가 나오는지 증명 필요 |
| M2 | **블록 수준 리스트 CRDT + 이동 연산** (Kleppmann 등의 move 연산, Loro MovableList 계열). 스토리를 "블록 리스트"로, 블록 안을 텍스트로 | 이동 의미론이 검증됨 | 문단 분할·병합이 다시 컨테이너 간 이동이 되어 01 §2의 장점을 잃음 |
| M3 | **이동 가능한 구간을 지원하는 자체 시퀀스 CRDT** | 원하는 의미론을 정확히 구현 | 연구 수준 난이도, 검증 비용이 큼 |

**결정 (ADR-0003, [V4 결과](../spikes/phase0-crdt.md))**: Loro 위의 M1(평평한 텍스트 + ¶)을 채택했다. 0단계 비교에서 M2는 분할·병합과 겹친 입력을 잃거나 복제했고(18개 중 유실 3, 중복 4), M1은 글자를 잃지 않았다(유실 0). 이동은 후속 실험에서 **평평한 텍스트 + 구획 순서**로 해결했다: 보이지 않는 구획 표식으로 텍스트를 나누고 화면 순서는 구획 ID 목록이 정하므로, 이동이 글자를 옮기지 않는다. 구획 ID를 구획을 **끝내는** 표식으로 정하면(M4) 문단을 떼어 내도 나머지 부분이 자리를 유지해, 서로 다른 문단을 동시에 같은 자리로 옮기는 경우도 보존된다(시나리오 30개 중 29개 통과, 유실·중복 0). 기준(anchor) 트리는 옮긴 구획이 뒤 구획을 끌고 가므로 쓰지 않는다. 구획 정리는 화면 계산에서 숨긴 구획을 건너뛰어 합쳐 보고(상태 변경 없음), 숨긴 내용은 실행 취소 기록에서 빠질 때 지우며, 구획 표식 자체는 편집 중에 지우지 않는다(동시 이동·숨김이 그 ID를 가리킬 수 있음). 표식은 정본 저장·새 판 압축 때 사라진다. 스토리 끝 ¶는 보이지 않는 보초 구획이 맡아 문단 삭제는 예외 없이 숨김이다빈 문서는 미리 만든 자리표시 문단을 보여 주어, 동시에 입력해도 같은 문단에 들어간다(시나리오 34개 모두 통과, 유실·중복 0).

## 4. 사용자별 실행 취소

- 각 피어는 **자기 origin의 트랜잭션만** 실행 취소 스택에 쌓는다.
- 실행 취소 = 해당 트랜잭션의 역연산을 **현재 문서 상태에 맞게 변환한 새 트랜잭션**을 만드는 것. 위치가 ID 기반이므로 다른 사용자의 편집 후에도 역연산 대상이 그대로 식별된다.
  - 삽입의 역: 그때 삽입한 원소 ID들 중 아직 살아 있는 것을 삭제
  - 삭제의 역: 그때 삭제한 원소들을 같은 위치(묘비 기준)에 **새 ID로 재삽입**하고 원래 ID → 새 ID 매핑을 남겨 주석·선택을 복구 (또는 CRDT가 지원하면 묘비 부활)
  - 서식·속성의 역: 이전 값을 기록해 두고, 그 사이 다른 사용자가 같은 속성을 바꿨으면 되돌리지 않는다(상대 변경 우선)
- 실행 취소 후 선택은 트랜잭션의 `selectionBefore`로 복원한다.

## 5. 변경 추적 (제안 모드)

제안 모드에서는 명령이 문서를 직접 바꾸지 않고 **제안 주석**을 남긴다.

| 사용자 행동 | 기록 방식 | 수락 | 거부 |
|---|---|---|---|
| 글자 입력 | 원소를 삽입하고 `suggestion:insert` 주석으로 감쌈 | 주석 제거 | 원소 삭제 |
| 글자 삭제 | 원소를 지우지 않고 `suggestion:delete` 주석 | 원소 삭제 | 주석 제거 |
| 문단 분할 | `¶` 삽입 + `suggestion:insert` | 주석 제거 | `¶` 삭제 (병합) |
| 문단 병합 | `¶`에 `suggestion:delete` | `¶` 삭제 | 주석 제거 |
| 서식 변경 | 서식을 적용하고 `suggestion:format` 주석에 이전 값 보관 | 주석 제거 | 이전 값 복원 |
| 블록 이동 | 이동 연산을 보류하고 `suggestion:move` 주석 (원본 구간 + 대상 위치) | 이동 실행 | 주석 제거 |
| 표 행·열 추가·삭제 | 행·열 원소에 삽입·삭제 제안 표시 | … | … |

- `¶`가 원소이기 때문에(01 §2) 분할·병합 제안이 글자 제안과 같은 방식이 된다. 이것이 평평한 열 모델을 택한 주된 이유다.
- 레이아웃은 "제안 포함 보기 / 최종본 보기 / 원본 보기" 세 모드를 지원한다. 보기 모드에 따라 삭제 제안 원소를 레이아웃에 포함할지 결정한다.

## 6. 버전 이력

- CRDT 업데이트 로그를 저장하고, 일정 간격(시간 또는 연산 수)으로 스냅샷을 만든다.
- 이름 붙인 버전 = 스냅샷 + 이름 + 작성자.
- 버전 비교: 두 시점의 원소 ID 집합 차이로 삽입·삭제를 정확히 구한다 (텍스트 diff 추정 불필요). 서식·속성 차이는 키별로 비교한다. 결과는 비영속 제안 주석으로 표시해 변경 추적과 같은 UI를 재사용한다.
- 복원: 대상 버전 상태로 가는 연산을 만들어 새 트랜잭션으로 적용한다 (이력을 지우지 않음).

## 7. 검증: 시나리오 테스트

수렴과 의도 보존은 단위 테스트로는 부족하다. 다음을 자동화한다.

- 결정적 랜덤 테스트: N개 피어가 무작위 연산을 하고 무작위 순서로 동기화 → 모두 같은 상태인지, 스키마 위반이 없는지
- 의도 시나리오 표 (예시):
  - 분할 ∥ 같은 문단 끝에 입력
  - 병합 ∥ 뒤 문단에 입력
  - 이동 ∥ 이동 대상 문단 편집
  - 이동 ∥ 이동 (같은 문단을 다른 위치로)
  - 표 행 삭제 ∥ 그 행의 셀 편집
  - 실행 취소 ∥ 원격 편집
  - 제안 수락 ∥ 제안 범위 편집
