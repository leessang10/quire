# 18. UI 다국어

- 상태: 초안 (구현 전)
- 범위: 편집기 화면의 글자(도구 막대, 대화상자, 도움말, 오류, 캔버스 표시, 접근성 이름)를 여러 언어로. 메시지 키와 번역 덮어쓰기 API.
- 범위 밖: 문서 안의 다국어 조판(언어 속성, 양방향 글자, 언어별 줄바꿈·글꼴 대체, 세로쓰기). 한글 조판(12 §9)과 따로 다룬다.
- 바탕: 04(렌더링·접근성), 08(통합·임베드), 17(테마: 공개 API 규칙을 같이 쓴다).

## 1. 목표

| # | 목표 | 끝났다는 기준 |
|---|---|---|
| L1 | 편집기 코드에 화면 문자열이 박혀 있지 않다 | 모든 화면 문자열이 메시지 키로 나온다 (검사 시험: 편집기 소스에 한글 문자열 리터럴이 없음, 주석 제외) |
| L2 | 한국어·영어 두 언어를 기본 제공 | 두 언어의 키 목록이 같다 (시험), 언어를 바꾸면 화면이 다시 그려진다 |
| L3 | 임베드하는 쪽이 번역을 덮어쓰거나 언어를 더할 수 있다 | `locale`·`messages` 옵션, 메시지 키가 공개 API로 문서화 |
| L4 | 언어를 바꿔도 문서는 그대로 | 레이아웃 지문·저장 결과가 같다 |

## 2. 원칙

- **UI 언어는 문서를 바꾸지 않는다.** 17 §2의 테마 원칙과 같다. 언어를 바꿔도 쪽 나눔·문서 내용·저장 바이트열이 그대로다.
  - 문서에 저장되는 이름(스타일 이름 `h1`, 목록 종류, 구역 ID)은 키다. 화면에 보일 때만 번역한다 ("제목 1" / "Heading 1").
  - 날짜 필드(12 §5)의 모양은 UI 언어가 아니라 **필드에 저장된 형식**을 따른다 (다른 언어 사용자가 같은 문서를 열어도 같은 모양, §8 O-46).
- **키는 의미 이름**: `break.page`, `dialog.pageSetup.title`처럼 점으로 나눈 영어 소문자. 문장 자체를 키로 쓰지 않는다 (문장이 바뀌면 키가 깨진다).
- **기본 언어는 한국어**, 빠진 키는 영어 → 키 이름 순으로 대신한다. 빠진 키는 개발 빌드에서 콘솔에 한 번 경고한다.
- **문자열 이어 붙이기 금지**: "구역 나눔 (" + 이름 + ")" 대신 자리표시가 있는 메시지 하나 (`break.section`: "구역 나눔 ({start})"). 어순이 언어마다 다르다.

## 3. 메시지 형식

- 값은 문자열, 자리표시는 `{이름}`. 복수형이 필요한 키만 ICU 비슷한 최소 문법을 쓴다:
  ```json
  {
    "break.section": "Section break ({start})",
    "status.pages": "{count, plural, one {# page} other {# pages}}"
  }
  ```
- 복수형은 `Intl.PluralRules`, 숫자는 `Intl.NumberFormat`, 날짜는 `Intl.DateTimeFormat`으로 UI 언어에 맞춘다. 한국어는 복수형이 없어 `other`만 쓴다.
- 전체 ICU MessageFormat(선택·중첩 등)은 넣지 않는다. 필요해지면 열린 질문으로 (§8).
- 번역 파일은 언어마다 평평한 JSON 하나: `packages/editor/src/i18n/ko.json`, `en.json`. 타입은 `ko.json`에서 키 목록을 뽑아 만든다 (`MessageKey`), 다른 언어 파일은 시험에서 키 집합을 비교한다.

## 4. 대상

| 곳 | 예 | 메모 |
|---|---|---|
| 캔버스 표시 | 쪽 나눔, 구역 나눔 (다음 쪽), 머리말 (첫 쪽) · 이전과 연결, 이미지 없음, 불러오는 중… | 캔버스가 그리므로 언어를 바꾸면 다시 그린다 (레이아웃은 그대로) |
| 기본 도구 막대·대화상자 | 쪽 설정, 용지, 여백, 시작 방식, 오류 문구 | 라이브러리가 제공하는 UI만. 앱이 만든 UI는 앱이 번역한다 |
| 스타일·목록 표시 이름 | 본문, 제목 1–3, 인용, 번호·글머리 | 저장 값은 키 그대로 (§2) |
| 접근성 | 미러의 역할 이름, 알림(라이브 영역) 문구, 단추 `aria-label` | 스크린 리더가 읽는 문장도 같은 메시지 |
| 단축키 표기 | Ctrl+Enter / ⌘↩ | 플랫폼에 따라 기호를 고른다. 키 자체는 번역하지 않는다 |
| 오류·진단 | 붙여넣기 실패, 글꼴 불러오기 실패 | 개발자 로그(`console`)는 영어 고정, 사용자에게 보이는 것만 번역 |

플레이그라운드는 앱 코드라 공개 API가 아니지만, 같은 메시지를 써서 시연한다.

## 5. API

```ts
const editor = new Editor({
  host,
  locale: 'en',                       // 기본 'ko'
  messages: { en: { 'break.page': 'Page break' } }, // 덮어쓰기·추가 언어
});
editor.setLocale('ko');               // 다시 그리기만, 레이아웃은 그대로
editor.t('dialog.pageSetup.title');   // 앱이 같은 번역을 쓰고 싶을 때
```

- `locale`은 BCP 47 태그 (`ko`, `en`, `en-GB`). 정확히 맞는 언어가 없으면 앞부분(`en`)으로 찾는다.
- 언어를 정하지 않으면 `navigator.language`가 아니라 **기본 `ko`**를 쓴다 (임베드하는 앱이 언어를 정하는 것이 맞다). 플레이그라운드는 브라우저 언어를 따른다.
- `messages`는 깊은 병합이 아니라 키 단위 덮어쓰기다. 새 언어는 키 전체를 줄 수 있고, 빠진 키는 §2의 순서로 대신한다.
- 호스트 요소에 `lang` 속성을 건다 (스크린 리더 발음, CSS `:lang()`). 17의 클래스 규칙과 같이 공개한다.
- 번역 묶음은 기본 언어만 같이 싣고, 다른 언어는 `import('@quire/editor/i18n/en')`처럼 따로 불러올 수 있게 한다 (묶음 크기).

## 6. 공개 키의 판 정책

17 §9 O-36과 같다: 메시지 키를 바꾸거나 지우면 한 판 동안 옛 키도 읽고(새 키가 있으면 새 키가 이긴다) 개발자 콘솔에 한 번 경고한 뒤, 다음 판에서 지운다. 바뀐 키는 변경 기록에 적는다. 번역 문장만 바뀌는 것은 판 정책 대상이 아니다.

## 7. 단계 계획

| 단계 | 내용 | 끝났다는 기준 |
|---|---|---|
| L-1 | 메시지 모듈과 `t()`, 편집기 코드의 문자열을 `ko.json` 키로 옮기기 (화면은 지금과 같음) | 소스 검사 시험 통과, 화면 그대로 (L1) |
| L-2 | `en.json`, `locale`·`messages`·`setLocale`, 복수형·숫자 | 키 집합 같음 시험, 언어 바꾸기로 다시 그리기 (L2·L3) |
| L-3 | 접근성 문구·단축키 표기, 호스트 `lang` | 스크린 리더로 두 언어 확인 |
| L-4 | 공개 키 표 문서화, 옛 키 경고 | 키 표와 `MessageKey` 타입이 같은 목록 (L3) |

- L-1은 작은 정리 작업이라 3단계(조판) 중에도 할 수 있다 (17의 T-1과 함께). 새 화면 문자열은 이 문서가 받아들여진 뒤부터 처음부터 키로 넣는다.

## 8. 열린 질문과 결정

- O-46. 날짜 필드 형식.
  - **결정**: Word·Google Docs 방식. 날짜 형식은 **필드마다** 개체 속성으로 저장한다 (예: `format: 'yyyy. M. d.'`). 넣을 때 형식 목록에서 고르고(목록은 지금 UI 언어의 흔한 형식들, 기본은 첫 항목), 나중에 필드를 눌러 바꿀 수 있다. 형식이 저장되므로 다른 언어 사용자가 열어도 같은 모양이다.
  - 날짜 값은 **보는 사람 컴퓨터의 시간대로 오늘** (Word의 DATE 필드와 같다). UTC를 쓰지 않는다: 한국에서 오전 9시 전에 전날 날짜가 보이는 문제가 없다.
  - Google Docs의 "고정 날짜"(넣은 날 그대로)는 필드 속성 `fixed: '2026-11-19'`로 둔다 (바뀌지 않는 날짜, 시간대 없음). 그리기 형식은 같은 `format`.
  - 이것은 필드 모델(12 §5.1)의 변경이라 구현은 조판 쪽 작업으로 한다. §2의 "문서 언어 설정 전까지 한국어 형식" 문장은 이 결정으로 바뀐다.
- O-47. 복수형 외에 값에 따라 단어가 바뀌는 문장 (예: 지운 것이 표인지 이미지인지에 따라 다른 문장).
  - **결정**: ICU `select` 문법은 넣지 않는다. 그런 문장은 키를 나눠 쓴다 (`delete.table`, `delete.image`).
- O-48. 오른쪽에서 왼쪽으로 쓰는 UI 언어(아랍어 등).
  - **결정**: 언젠가 지원한다. 그래서 L-1부터 기본 UI의 CSS는 `left`·`right` 대신 논리 속성(`margin-inline-start`, `inset-inline-end` 등)을 쓰고, 도구 막대·대화상자 배치는 호스트의 `dir="rtl"`로 뒤집힐 수 있게 만든다. 캔버스 문서 조판(문서 안의 양방향 글자)과는 별개다.
- O-49. 번역 파일을 누가 어디서 고칠지.
  - **결정**: 저장소 안의 JSON(`ko.json`, `en.json`)을 개발자가 직접 고친다. 번역 관리 사이트 연동은 언어가 많아지면 다시 본다.
