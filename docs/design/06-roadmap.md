- 상태: 초안

## 1. 단계 요약

|---|---|---|---|
| 0 | 기술 검증 (가장 위험한 가정부터) | L3, O-1, O-2 | §2의 검증 항목 통과 또는 설계 수정 |

접근성 미러(04 §3)는 1단계부터 각 단계의 완료 기준에 포함한다.

## 2. 0단계: 기술 검증

### 만들 것
캔버스 위의 단일 스토리 편집기 (서식 없음, 쪽 나눔 없음).

- 문서 모델 최소 구현: 원소 열 + `¶` + ID 기반 위치
- `measureText` 기반의 단순 줄바꿈 레이아웃 (한글 어절 단위)
- 캔버스 렌더링, 캐럿, 마우스·키보드 선택
- 입력 층 경로 A(EditContext)와 경로 B(숨긴 textarea)
- 접근성 미러 최소 구현
- 동기화 프로토타입 2개 (05 §3의 M1, M2)

### 검증 항목

| # | 항목 | 통과 기준 |
|---|---|---|
| V1 | 한글 IME | 아래 환경에서 정해진 입력 스크립트(조합 중 백스페이스, 조합 중 클릭, 조합 중 방향키, 빠른 연타, 자동 수정)를 수행해 결과 문자열이 기대값과 일치 |
| V2 | 후보 창 위치 | 한자 변환·이모지 후보 창이 캐럿 근처에 표시 |
| V3 | 접근성 | NVDA + Chrome, VoiceOver + Safari에서 문단 읽기, 캐럿 이동 시 현재 글자·줄 읽기 |
| V4 | 동기화 의도 보존 | 05 §7 시나리오 표를 M1, M2 모두에 실행해 결과 비교 → ADR-0003 결정 (**완료**: [결과](../spikes/phase0-crdt.md)) |
| V5 | 성능 기초 | 10만 문단 문서에서 입력 → 화면 반영 16ms 이내 (레이아웃은 문단 단위 증분만) |

현황 (2026-11-17): V4 완료, V5 엔진 기준 충족, V1 부분(합성 이벤트), V2·V3 실제 환경 미확인. 자세히는 [0단계 결과](../spikes/phase0-baseline.md).

| iOS | Safari | 기본 키보드 |
| Android | Chrome | Gboard, 삼성 키보드 |

## 3. 성능 목표

| 지표 | 목표 | 측정 조건 |
|---|---|---|
| 입력 지연 (키 → 화면) | p95 16ms 이하 | 1,000쪽 문서, 문서 중간에서 연속 입력 |
| 초기 표시 | 첫 화면 1초 이내 | 1,000쪽 문서 열기 (나머지 쪽은 백그라운드 조판) |

## 4. 주요 위험

| 위험 | 영향 | 완화 |
|---|---|---|
| 모바일 IME 호환성 | 모바일에서 사용 불가 | 0단계 실기기 검증, 브라우저별 보정 표 + 재현 테스트 |
| 블록 이동 CRDT 의미론 | L8 미해결, 데이터 유실 | 0단계 M1/M2 비교, 랜덤 수렴 테스트 상시 실행 |
| 기기 간 쪽 나눔 불일치 | 협업 문서 신뢰성 상실 | 글꼴 직접 로드, 정수 단위, 레이아웃 골든 테스트 (여러 OS·브라우저에서 같은 결과인지) |
| 고급 조판의 범위 폭발 | 3단계가 끝나지 않음 | "기준 문서 세트"(실제 보고서·논문 N종)를 정하고 재현율로 완료 판단 (02 O-7) |
| 접근성 요건 | 기관 납품 불가 | 0단계 V3, 1단계부터 완료 기준에 포함 |
| 한글 웹폰트 용량 | 첫 표시 지연 | 부분 로드, 임시 메트릭 후 재조판 |
