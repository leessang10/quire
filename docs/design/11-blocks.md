# 11. 블록 (2단계 2부)

- 상태: 초안
- 범위: 06 2단계의 나머지. 이미지(인라인), 떠 있는 이미지와 어울림, 표(쪽 분할 제외), 다중 커서.
- 바탕: 01(문서 모델), 02(레이아웃), 03(입력·선택), 05·09(동시 편집), 07(파일), 10(서식).

## 1. 목표

| # | 목표 | 끝났다는 기준 |
|---|---|---|
| G1 | 인라인 이미지: 글자처럼 줄 안에 놓이고, 크기 조절·대체 텍스트·붙여넣기·끌어 놓기 | 1,000쪽 문서에 이미지 1,000개: 입력 p95 16 ms, 이미지를 불러오기 전후 쪽 나눔 같음 |
| G2 | 떠 있는 이미지와 어울림: 문단·쪽에 붙고 글이 둘레로 흐름 (자리 차지, 어울림, 글 앞·뒤) | 이미지를 옮기면 그 쪽의 줄만 다시 나눔, 기기 간 같은 쪽 나눔(결정성 지문) |
| G3 | 표: 행·열 추가·삭제·이동, 셀 병합·나누기, 열 너비, 셀 안 서식 문단 | 동시 편집 시나리오(§3.3) 통과, 행 1,000개 표에서 셀 입력 p95 16 ms |
| G4 | 다중 커서: 여러 캐럿에서 입력·삭제·서식, 실행 취소 한 단계 | 캐럿 100개 입력 p95 16 ms, 한글 조합은 첫 캐럿에서 하고 확정 때 모두에 |

표 행을 쪽 사이에서 쪼개기와 제목 행 반복, 머리말·각주 안의 개체는 3단계다. 2단계 표는 **행 사이에서만** 쪽을 나눈다.

## 2. 모델

01 §2의 원소 종류를 그대로 쓴다. **개체는 원소 하나**이고, 개체의 속성은 그 원소에 붙는다(¶의 문단 속성과 같은 방식).

### 2.1 개체 원소

| 원소 | 코드 | 문단 안에서 | 속성 (키) |
|---|---|---|---|
| 인라인 개체 | U+FFFC | 글자 한 칸, 폭 = 개체 폭 | `kind: 'image'`, `asset`, `w`, `h`, `alt`, `crop?` |
| 앵커 (떠 있는 개체) | U+FFFC | 폭 0, 캐럿은 건너뜀 | 위 + `float` (§2.3) |
| 표 | U+E002 | 문단 하나를 혼자 차지 (§2.4) | `kind: 'table'`, `table` (표 ID) |

- 개체 원소는 서식 묶음 번호(fmt)를 그대로 갖는다. 밑줄·링크는 인라인 개체에도 걸린다. 크기 서식은 무시한다.
- 개체 속성은 Doc의 맵 `원소 카운터 → ObjAttrs`다 (10 §2.2의 `paraAttrsMap`과 같은 구조).
- 실행 취소 연산은 `{ type: 'obj', ctr, key, before, after }`다.
- 지운 개체(묘비)도 속성을 기억한다. 되살리면 그대로 돌아온다.
- 길이 단위는 1/1000pt다. 이미지 원래 크기(px)는 자산에 있다. 문서의 `w`·`h`는 놓인 크기다.
- `ParagraphInfo`에 `objs: Int32Array | null`(문단 안 개체 원소의 코드포인트 위치)을 더한다. 개체가 없는 문단은 지금과 같다.

### 2.2 자산 (이미지 원본)

- 원본 바이트는 **CRDT에 넣지 않는다**. 자산 ID는 내용의 SHA-256(16진 앞 32자)이다. 같은 이미지는 한 번만 저장한다.
- 문서에는 자산 맵 `assets: ID → { mime, px: [w, h], bytes }`만 둔다 (Loro 맵, 값은 바뀌지 않음).
- 바이트는 따로 둔다.
  - 서버: `PUT /<방>/assets/<ID>`, `GET /<방>/assets/<ID>`. 방 저장소에 내용 주소 파일로 둔다.
  - 클라이언트: IndexedDB 캐시(`quire-assets`). 오프라인에서 넣은 이미지는 연결되면 올린다.
  - `.quire`: `assets/<ID>.<확장자>` (07 §2). 정본 JSON은 ID만 가리킨다.
- 이미지를 넣으면 먼저 자산 바이트를 로컬 캐시에 넣고, 개체 원소를 넣고, 바이트 올리기를 기다리지 않는다. 다른 피어는 바이트가 올 때까지 자리표시(회색 상자 + 대체 텍스트)를 그린다. 크기는 문서에 있으므로 **쪽 나눔은 바이트와 무관하다**.
- 너무 큰 이미지: 긴 변 4,096px로 줄인 사본을 자산으로 넣는다. 원본 유지 여부는 07 O-17과 함께 정한다.

### 2.3 떠 있는 개체

```ts
interface Float {
  /** 무엇에 대한 위치인가 */
  relX: 'column' | 'margin' | 'page';
  relY: 'paragraph' | 'margin' | 'page';
  /** 기준에서 개체 왼쪽 위까지 (1/1000pt). x는 정렬로도 줄 수 있다 */
  x: number | 'left' | 'center' | 'right';
  y: number;
  wrap: 'square' | 'topBottom' | 'none';
  /** square일 때 글이 흐를 쪽 */
  side?: 'both' | 'left' | 'right' | 'largest';
  /** 개체와 글 사이 간격 */
  gap?: number;
  /** wrap none일 때 글 앞인가 뒤인가 */
  behind?: boolean;
}
```

- 앵커는 개체가 붙은 문단을 정한다. 문단이 움직이면(입력, 문단 이동) 개체도 따라 움직인다 (`relY: 'paragraph'`).
- `relY: 'page'`인 개체도 앵커 문단이 놓인 쪽에 놓인다. 앵커를 옮기면 그 쪽으로 간다 (Word와 같다).
- 쪽 위치는 문서에 저장하지 않는다. 위치는 (기준, 거리)이고 실제 쪽은 조판이 정한다.

### 2.4 표

01 §2: 표는 원소 하나이고 셀 스토리를 참조한다. 표 원소는 **문단 하나를 혼자 차지한다**: `[U+E002][¶]`.

- 이렇게 하면 문단 기계(구획, 이동, 숨김, 목록 번호)를 그대로 쓴다. 표 옮기기 = 문단 옮기기, 표 지우기 = 문단 숨기기(되돌리면 셀 내용까지 그대로).
- 편집기는 그 문단에 글자를 넣지 못하게 한다. 캐럿은 표 앞(앞 문단 끝)이나 표 안(셀)에 선다.
- 표 구조는 Doc 밖의 **표 레코드**다.

```ts
interface Table {
  id: string;
  rows: RowId[];                 // 순서 (MovableList). 지운 행도 남는다
  cols: ColId[];
  /** 지운 행·열 (표시만, 목록에서 빼지 않음) */
  gone: Record<RowId | ColId, true>;
  colWidth: Record<ColId, number>;           // 1/1000pt
  rowAttrs: Record<RowId, { minHeight?: number; header?: true }>;
  /** 병합: 왼쪽 위 셀 → 덮는 행·열 ID 목록 */
  spans: Record<`${RowId}|${ColId}`, { rows: RowId[]; cols: ColId[] }>;
  cellAttrs: Record<`${RowId}|${ColId}`, CellAttrs>;
  attrs: { width?: 'auto' | number; align?: 'left' | 'center'; border?: Border; style?: string };
}
// 셀 (행, 열)의 스토리 ID = `${표}|${행}|${열}` (레코드에 두지 않는다)
```

- 행·열 ID는 만들 때 정하고 바뀌지 않는다. 행·열 삽입은 목록에 ID 하나 넣기, 이동은 옮기기다.
- **삭제는 지운 표시**다 (`gone`). 목록에서 빼면 동시 이동이 삭제를 이겨 행이 되살아난다 (스파이크 T8). 되돌리기는 표시를 지우고, 행이 제자리로 돌아온다.
- 행을 지워도 그 행의 셀 스토리는 남는다. 되돌리면 그사이 들어온 입력까지 보인다.
- **셀 스토리 ID는 (표, 행, 열)에서 정해진다.** 동시에 행과 열을 넣어 생긴 교차 칸에 두 사람이 처음 입력해도 같은 스토리다 (스파이크 T9). 셀을 미리 만들지 않는다. 처음 입력할 때 생긴다.
- **병합**: 왼쪽 위 셀의 `spans` 항목이다. 범위는 덮는 행·열 ID 목록이다. 칸 수로 두면 가운데 행을 지울 때 병합이 다음 행까지 늘어난다.
  - 병합은 **덮인 셀의 글을 옮기지 않는다.** 옮기기(지우고 넣기)는 동시 병합에서 같은 글을 두 번 넣는다 (스파이크 무작위: 40시드 중 22개에서 글 44개가 중복, 옮기지 않으면 0).
  - 레이아웃은 **덮인 셀 중 비지 않은 것의 문단을 왼쪽 위 셀 내용 뒤에 이어 그린다**. 캐럿은 그 문단에 들어가 그 셀 스토리를 고친다.
  - 나누기 명령은 `spans` 항목을 지운다. 덮였던 글은 원래 셀에 그대로 있다.
- **정규화** (읽을 때, 저장하지 않음): 겹치는 병합은 행 우선 순서로 앞의 것이 이긴다. 병합 범위는 목록의 행·열 중 남은 것 가운데 가장 먼 것까지다.

### 2.5 여러 스토리

지금 Doc은 스토리 하나다. 셀마다 스토리가 생기므로 **Document = 스토리들의 모음**을 둔다.

```ts
class Document {
  body: Doc;
  stories: Map<StoryId, Doc>;   // 'cell:…' (3단계에 머리말·각주·글상자)
  tables: Map<TableId, Table>;
  assets: Map<AssetId, AssetInfo>;
}
```

- 각 스토리는 지금의 Doc을 그대로 쓴다 (구획, 서식, 실행 취소 연산). 셀 안에서도 문단 이동·목록·스타일이 된다.
- `Position`에 `story`를 더한다 (01 §3.2에 이미 있다). 선택·캐럿·원격 캐럿이 스토리를 가진다.
- 실행 취소 트랜잭션은 여러 스토리의 연산을 함께 담는다 (`{ story, op }`). 표 구조 연산(`row`, `col`, `span`, `width`)도 같은 트랜잭션에 든다.
- 스토리는 표 레코드에서만 만든다. 셀 스토리의 기본 내용은 빈 문단 하나다.

## 3. 동시 편집 (Loro)

### 3.1 표현

| 모델 | Loro |
|---|---|
| 개체 원소 | 텍스트의 U+FFFC / U+E002 글자 |
| 개체 속성 | 그 글자의 마크 `o_<키>` (expand none). **개체 글자에 붙은 것만 읽는다** (¶의 `p_`와 같은 이유, 10 §3) |
| 자산 정보 | 맵 `assets` |
| 표 레코드 | 루트 컨테이너 `<표>.rows`·`<표>.cols`(MovableList), `<표>.gone`·`<표>.w`·`<표>.rowAttrs`·`<표>.span`·`<표>.cellAttrs`(맵). 루트 이름에는 `/`를 쓸 수 없다 |
| 셀 스토리 | 텍스트 `s:<표>\|<행>\|<열>`. 구획 표식 없이 가볍게 시작하고, 셀 안에서 처음 문단을 옮길 때 구획 순서 `o:<스토리>` 등을 만든다 |

- 브리지·Worker는 이벤트의 컨테이너 ID로 스토리를 찾는다. 위치 변환(ot.ts)은 스토리마다 따로 한다.
- 표 구조 변경은 메시지에 `table` 항목으로 싣는다 (정의 맵처럼 바뀐 표 레코드를 통째로). 표 하나는 작다.

### 3.2 개체

- 크기·대체 텍스트·위치는 키마다 LWW다. 두 사람이 동시에 크기를 바꾸면 나중 것이 이긴다.
- 개체 글자를 지우는 동안 다른 사람이 크기를 바꾸면 묘비의 속성이 바뀐다. 되살리면 바뀐 크기로 돌아온다.
- 떠 있는 개체를 끌어 옮기면 앵커가 다른 문단으로 갈 수 있다: **앵커 원소를 지우고 새 자리에 넣는다**(속성 복사). 동시에 둘이 옮기면 개체가 둘이 된다. 개체 ID(속성 `id`)가 같은 것이 둘이면 레이아웃은 앞의 하나만 그리고, 편집기가 다음 편집 때 뒤의 것을 지운다 (09의 자리표시 정리와 같은 방식).

### 3.3 표 시나리오 (스파이크 2-7: **15/15 통과**, [후속 7](../spikes/phase0-crdt.md#후속-7-블록-의미론-2단계-2-7))

결과에 따라 고친 표현: 삭제는 지운 표시(T8), 셀 스토리 ID는 (표, 행, 열)에서 정함(T9), 병합은 글을 옮기지 않음(무작위 시험). 무작위 동시 편집 8,000연산이 수렴했고 셀 글 유실·중복은 0이었다.

| # | A | B (동시) | 기대 |
|---|---|---|---|
| T1 | 행 r 삭제 | r의 셀에 입력 | 행은 없음. B의 글은 셀 스토리에 남고, A가 되돌리면 보임 |
| T2 | r 뒤에 행 추가 | r 뒤에 행 추가 | 행 두 개 (피어 순서) |
| T3 | (1,1)–(1,2) 병합 | (1,2)에 입력 | 병합. (1,2)의 글(B 포함)은 왼쪽 위 셀 뒤에 이어 보임 |
| T4 | 열 c 삭제 | c를 지나는 병합 | 병합이 남은 열로 줄어듦 |
| T5 | 표 옮기기(문단 이동) | 셀에 입력 | 옮긴 표에 입력 |
| T6 | 표 삭제(숨김) | 셀에 입력 | 표 없음. 되돌리면 B의 입력까지 |
| T7 | 열 너비 바꾸기 | 열 추가 | 새 열은 기본 너비, 둘 다 반영 |
| T8 | 행 r 이동 | r 삭제 | 삭제 (이동은 없는 항목에 대해 무시) |
| T9 | 행 추가 | 열 추가 | 교차 칸은 빈 셀 (처음 입력 때 만듦) |
| T10 | 셀 나누기 | 같은 셀에 입력 | 이어 그리던 글이 원래 셀에 |
| O1 | 이미지 크기 | 같은 이미지 크기 | 나중 것 |
| O2 | 앵커 문단 삭제 | 그 이미지 옮기기 | 이미지 하나 (옮긴 자리) 또는 없음, 두 피어 같음 |

통과하지 못하는 시나리오는 표현을 바꾼다 (예: 병합을 셀 속성 대신 별도 맵으로).

## 4. 레이아웃

### 4.1 인라인 개체

- 셰이핑에서 개체 글자는 조각을 끊는다 (공백처럼). 진행폭 = `w`, 줄바꿈 기회 = 앞뒤 모두.
- 줄 높이: 개체는 기준선 위에 선다 (ascent = h, descent = 0). 줄 높이 = max(글자 줄 높이, 개체 높이 + descent). 10 §4의 줄 배율 대신 **줄마다 ascent·descent 최댓값**을 쓰도록 `LineBox`를 넓힌다 (배율은 글자 크기에서 구한 ascent·descent로 바뀐다).
- 줄보다 넓은 이미지는 줄 폭으로 줄여 그린다 (문서 값은 그대로, 경고 표시). 쪽보다 높은 이미지도 같다.
- 결정성: 개체 폭·높이는 문서의 정수(1/1000pt)에서 px로 바꾼 값이다. 이미지 바이트와 무관하다.

### 4.2 떠 있는 개체와 어울림 (02 §5 LineSpace)

- **줄 폭 함수**: 문단 레이아웃은 지금 (첫 줄 폭, 나머지 줄 폭)을 받는다. 이것을 `slotsAt(y, h)`로 넓힌다. 개체가 없는 쪽에서는 지금과 같은 상수 폭이다.
- **두 단계 줄바꿈**: 셰이핑·글자 위치(`xs`)는 지금처럼 폭과 무관하게 캐시한다. 줄바꿈만 다시 한다.
  - 배제 영역이 없는 문단은 캐시한 줄 나눔을 그대로 쓴다.
  - 배제 영역과 y가 겹치는 문단은 놓으면서 줄마다 그 자리의 빈 구간으로 줄을 나눈다 (`breakLinesAt`).
- **빈 구간**: `square`는 개체 사각형 + gap을 배제한다. `side`에 따라 왼쪽·오른쪽·둘 다·넓은 쪽이 남는다.
  - `both`는 한 y에 구간이 둘이다. 줄 하나가 왼쪽 구간을 채우고 이어서 오른쪽 구간을 채운다 (한 줄이 두 조각).
  - `topBottom`은 개체 높이 전체가 비어 글이 아래로 내려간다. `none`은 배제하지 않는다.
- **배치 순서** (쪽마다):
  1. 문단을 놓다가 앵커를 만나면 개체를 놓을 자리(쪽 좌표)를 계산하고 배제 영역을 등록한다.
  2. 개체가 이미 놓은 줄(같은 문단의 앞 줄, `relY`가 위쪽인 경우 앞 문단)과 겹치면 그 쪽의 해당 문단부터 다시 놓는다.
  3. 쪽마다 최대 3회 반복하고 고정한다 (02 §6). 고정된 경우는 진단 기록에 남긴다.
- 증분: 쪽 끝 상태(02 §7)에 "다음 쪽으로 넘어가는 배제 영역"을 넣는다. 수렴 판단이 이것까지 비교한다.
- 그리기 순서: `behind` 개체 → 글 → 나머지 개체. 선택한 개체는 손잡이(크기 조절 8곳, 회전 없음)를 그린다.

### 4.3 표

- 표 문단은 줄 하나 대신 **표 상자**를 놓는다. 높이 = 행 높이의 합.
- 열 너비: 문서의 `colWidth`. 합이 본문 폭보다 크면 비율로 줄인다 (문서 값은 그대로). `auto` 너비는 3단계.
- 셀 레이아웃: 셀 스토리의 문단들을 (열 너비 − 셀 여백)으로 조판한다. 지금의 문단 레이아웃·서식·목록을 그대로 쓴다. 셀마다 작은 PagedLayout이고 쪽 나눔은 없다.
- 행 높이 = max(최소 높이, 그 행에서 끝나는 셀들의 내용 높이). 병합 셀은 걸친 행 높이의 합이 모자라면 마지막 행을 늘린다.
- **쪽 나눔**: 행 사이에서만 한다. 행이 남은 공간보다 크면 다음 쪽으로 넘긴다. 쪽보다 큰 행은 넘치게 그리고 경고한다 (행 쪼개기는 3단계).
- 증분: 셀 입력은 그 셀 레이아웃 → 그 행 높이 → (높이가 같으면) 끝. 높이가 바뀌면 표 상자 높이가 바뀌어 지금처럼 뒤 문단을 다시 놓는다.
- 표 안의 떠 있는 개체는 3단계다 (2단계는 셀 안 인라인 이미지까지).

## 5. 편집기

### 5.1 선택 (03 §4)

```ts
type Selection =
  | { kind: 'text'; ranges: Array<{ anchor: Position; head: Position }>; primary: number }
  | { kind: 'cells'; table: TableId; anchor: CellRef; head: CellRef }
  | { kind: 'object'; story: StoryId; object: ElementId };
```

- 지금의 `{ anchor, head }`는 `ranges` 하나인 경우다.
- 개체 선택: 이미지를 누르면 개체 선택이 된다. 손잡이로 크기 조절(Shift: 비율 유지), Delete로 지우기, 화살표로 캐럿으로 돌아간다.
- 셀 선택: 셀 경계를 넘어 끌면 셀 사각형 선택이다. 서식·병합·지우기가 사각형에 걸린다.

### 5.2 다중 커서

- 추가: Alt+클릭, Ctrl+Alt+↑/↓ (위·아래 줄에 캐럿). Esc는 첫 캐럿만 남긴다. Alt+Shift+↑/↓는 문단 이동 그대로다.
- 입력·삭제·서식은 **뒤 캐럿부터** 적용해 앞 캐럿 위치가 그대로 맞게 하고, 트랜잭션 하나로 기록한다.
- 한글 조합: 조합은 첫 캐럿(입력 층이 놓인 곳)에서만 보이고, 확정한 문자열을 모든 캐럿에 넣는다. 다른 캐럿 자리에는 조합 중 문자열을 흐리게 미리 그린다.
- 겹치는 범위는 합친다. 캐럿 수 상한은 1,000개다.
- 원격 프레즌스는 첫 캐럿만 보낸다 (프레즌스 크기).

## 6. 저장

- 정본 JSON (07 §4)
  - 인라인 이미지: 런 배열 `c`에 `{ "img": { "asset": "…", "w": …, "h": …, "alt": "…" } }`.
  - 떠 있는 이미지: 같은 런에 `"float": {…}`.
  - 표: 본문 배열에 `{ "table": { "cols": [너비…], "rows": [ { "cells": [ { "story": "c1", "span": [1, 2] } ] } ] } }`. 셀 스토리는 `stories`에.
  - 행·열 ID, 덮인 셀, 정규화 전 상태는 저장하지 않는다. 정본은 정규화한 결과다. 열면 새 ID를 만든다.

## 7. 접근성

- 인라인·떠 있는 이미지: 미러에 `img`(alt). 대체 텍스트가 없으면 "이미지"로 읽고 편집기에 경고 표시.
- 표: 미러에 `table`·`tr`·`td`, 제목 행은 `th`. 병합은 `rowspan`·`colspan`.
- 다중 커서: 첫 캐럿만 입력 층·스크린리더에 알린다. 캐럿 수는 상태 표시로 알린다.

## 11. 2-8 결과: 인라인 이미지

### 구현

- **모델** (`Doc`):
  - 개체 원소 U+FFFC (`OBJ`), 속성 맵 `원소 카운터 → ObjAttrs { id, kind, asset, w, h, alt }`.
  - `insertObject`, `objAt`, `setObjAttr`, 연산 `{ type: 'obj' }`.
  - `ParagraphInfo.objs`(문단 안 위치 → 속성)가 있다. 속성을 바꾸면 그 문단만 새 객체가 된다.
  - 지운 개체도 속성을 기억해, 되살리면(실행 취소) 속성 변경 기록도 다시 보낸다.
  - `paragraphRuns`·`fromParagraphRuns`에서 개체는 혼자 한 런이다.
- **동기화**:
  - 개체 속성은 개체 글자의 마크 `o_<키>`(expand none)다. 받는 쪽은 개체 글자에 붙은 것만 읽는다 (스파이크 O4).
  - 위치 변환에서 `obj`는 `para`처럼 글자 하나이고, 같은 키의 원격 `format`에서는 로컬이 이긴다.
  - 정본 JSON 런은 `{ "img": {…}, "m": {…} }`다. 압축·재기반(`syncFormats`)도 개체 속성을 옮긴다.
- **자산**:
  - ID = 내용 SHA-256 앞 32자.
  - 서버 `GET/PUT /<방>/assets/<ID>`: 내용과 ID가 맞는지, 이미지 형식인지, 20 MB 이하인지 확인한다. 방 디렉터리의 `assets/`에 둔다.
  - `.quire`의 `assets/<ID>.<확장자>`: 서버 내려받기는 문서가 가리키는 자산을 넣고, 올리기는 방 저장소로 옮긴다. 열 때 이름과 내용이 다르면 버리고 진단에 적는다.
  - 편집기 `AssetStore`:
    - `MemoryAssets`(기본).
    - `HttpAssets`: IndexedDB 캐시. 넣으면 바로 캐시에 두고 올리기는 뒤에서 하며, 실패하면 다음 접근이나 온라인이 될 때 다시 한다.
  - **설계와 다른 점**: Loro 맵 `assets`는 두지 않았다. MIME은 저장소가 알고, 크기는 문서의 `w`·`h`라 문서에 더 둘 것이 없었다.
- **레이아웃**:
  - 개체는 조각을 끊고 진행폭 = 폭이다. 앞뒤 모두 줄바꿈 기회이고, 줄보다 넓으면 비율대로 줄인다.
  - 줄에 `objH`(개체 최대 높이)가 있고, 줄 높이는 개체 높이 − 글자 ascent만큼 늘어난다. 기준선도 그만큼 내려가 개체가 기준선 위에 선다. 고정 줄 간격(exact)은 늘리지 않는다.
  - 크기가 캐시 키에 들어간다. 개체 없는 문단은 전과 같은 경로이고 지문 셋도 그대로다.
- **편집기**:
  - 이미지 그리기: 원본을 불러오는 동안은 대체 텍스트를 쓴 회색 상자이고, 없으면 "이미지 없음"이다. 64개가 넘으면 이번 프레임에 그리지 않은 비트맵을 푼다.
  - 넣기: `insertImage(blob, alt?)`(본문 폭보다 넓으면 줄임), 붙여넣기(클립보드 이미지), 끌어 놓기(놓은 자리).
  - 누르면 개체 선택이 되고 손잡이 8곳이 나온다.
    - 모서리는 비율 유지, 변은 한 방향이다 (**설계와 다른 점**: Shift 대신 모서리가 비율 유지. Word·한글과 같다).
    - 크기 조절은 실행 취소 한 단계다.
  - `setObjectAttr`(대체 텍스트 등), `selectedObject`.
  - 접근성 미러는 개체를 `role="img"`와 대체 텍스트(없으면 "이미지")로 낸다.
- **놀이터**: "이미지 넣기"·"대체 텍스트" 단추, 서식 예제에 이미지 두 개. 실시간 편집 페이지는 서버 자산 저장소를 쓴다.

### 구현

- **모델**: 개체 속성 `float: FloatAttrs { relX, relY, x, y, wrap, side, gap, behind }` (1/1000pt). 값 하나라 동기화·실행 취소·정본 JSON(`img.float`)은 2-8 그대로다.
- **레이아웃 입력**: `ParaFormat.floats`(앵커 위치 → `FloatSpec`, px). 앵커는 폭 0이다 (인라인 개체 표에 폭 0으로 넣어 진행폭·줄바꿈이 같은 길을 탄다).
- **자리**: 문단 첫 줄이 놓일 쪽·y 기준이다.
  - `relX`: column·margin(본문 영역), page(쪽 왼쪽). `x`는 거리나 left·center·right다.
  - `relY`: paragraph(문단 위쪽), margin, page.
  - 쪽은 저장하지 않는다.
- **배제 영역**: 쪽마다 둔다 (`FloatRegistry`). square는 개체 + gap 사각형이고, topBottom은 그 높이 전체 폭, none은 없다.
  - **앞 문단의 개체만 뒤 문단에 영향을 준다** (같은 문단 포함). 그래서 반복 수렴이 필요 없다: 개체가 이미 놓은 줄을 다시 밀지 않는다.
- **어울림 줄바꿈**: 문단을 놓다가 배제 영역과 겹치는 줄을 만나면 그 줄부터 다시 나눈다.
  - 줄마다 그 y의 빈 구간을 찾는다: 기본 줄 높이로 보고, 넓은 쪽 또는 left·right이고, 24px보다 좁으면 막힌 것으로 보고 영역 아래로 내려간다.
  - 그 폭으로 `breakFrom`(같은 줄바꿈 규칙: 어절, 개체 앞뒤, 글자 단위 + 금칙)으로 나눈다.
  - 셰이핑 결과(`xs`)와 문단 캐시는 그대로 쓴다.
  - 정렬·양쪽 맞춤·들여쓰기는 빈 구간 안에서 한다.
- **증분**: 배제 영역은 놓인 문단이 소유하고, 다시 놓거나 지우면 함께 빠진다.
  - 수렴 판단은 (쪽, y)에 더해 **그 문단이 본 배제 영역 서명**이 같을 때만 앞 결과를 그대로 쓴다.
  - 레이아웃 캐시 키에 떠 있는 개체가 들어간다 (브라우저 시험에서 찾음: 처음에는 빠져 배치를 바꿔도 옛 줄 나눔이 쓰였다).
- **편집기**:
  - 글 뒤 개체는 글보다 먼저, 나머지는 글 다음에 그린다.
  - 누르면 선택(손잡이, 크기 조절은 2-8 그대로)이고, 선택한 개체를 끌면 옮긴다.
    - 같은 문단 위에 놓으면 위치(`x`, `y`)만 바꾼다.
    - 다른 문단 위에 놓으면 그 문단 첫머리로 앵커를 옮긴다 (지우고 넣기, 속성 복사, 실행 취소 한 단계).
  - 선택하면 앵커 문단에 ⚓를 표시한다.
  - `setPlacement(inline | square | topBottom | front | behind)`.
  - 놀이터에는 "배치" 선택 상자가 있고, 서식 예제에 어울림 이미지가 있다.
- 결정성 지문 모듈 `packages/shaping/src/fingerprint.ts`: 시험과 브라우저가 같은 코드를 부른다.

## 13. 2-10 결과: 여러 스토리

### 구현

- **가벼운 스토리** (`Doc.fromRaw(…, story = true)`):
  - 본문이 아닌 스토리는 보초·자리표시 없이 시작한다. 빈 Loro 텍스트가 빈 문단 하나다.
  - 끝 ¶는 Loro 텍스트에 없는 **유령 ¶**다. 두 피어가 같은 스토리(같은 ID: 표 셀)를 동시에 처음 만들어도 넣는 구조 글자가 없어 합쳐진다.
  - 유령 ¶의 문단 속성·서식은 Loro 텍스트에 걸 글자가 없다. 그래서 맵 `tp:<스토리>`(키 = `p_<속성>` 또는 서식 키)에 두고, 변경 기록은 `{ kind: 'tail' }`다.
  - 지우기는 유령 ¶ 앞까지다 (본문의 끝 ¶와 같은 규칙). 끝 문단은 옮기거나 숨기지 않는다.
  - 구획은 셀 안에서 처음 문단을 옮길 때 생긴다 (Loro 순서 목록에 END가 없어도 된다).
- **Document** (`@quire/model`): 본문 Doc + 스토리 Doc들, `story(id)`(없으면 만듦), `storyIds`, `observe((story, change))`.
  - 실행 취소 연산은 `{ type: 'story', story, op }`로 감싸고 `Document.apply`가 그 스토리에 적용한다.
  - `History.undo/redo`는 `OpTarget`(Doc 또는 Document)을 받는다. 한 트랜잭션에 여러 스토리의 연산을 담는다.
- **Loro 이름**: 스토리마다 `s:`(텍스트), `so:`(순서), `sh:`·`sp:`·`su:`(숨김·자리표시·사용), `tp:`(끝 ¶) + 스토리 ID. 본문은 옛 이름 그대로다. 스타일·목록 정의 맵은 문서에 하나다.
- **같은 스레드 브리지**:
  - `bridge.document`, `bridge.story(id)`. 스토리는 처음 열 때 Loro 상태에서 만들고, 그 뒤 컨테이너 ID로 이벤트를 그 스토리에 보낸다.
  - 열지 않은 스토리의 이벤트는 버린다 (열 때 읽는다). 스토리마다 쓰기(`LoroWriter`의 이름)가 따로다.
- **Worker 경로**:
  - 변경·원격 연산에 `story`가 붙는다. 위치 변환은 스토리가 다르면 서로 영향이 없다.
  - Worker는 컨테이너 이름으로 스토리를 찾고, init·reset에 모든 스토리의 처음 상태를 싣는다. 원격 항목·ack에는 스토리별 구획 상태와 **끝 ¶ 맵 전체**를 싣는다.
  - 메인은 Document로 모든 스토리를 비춘다. 로컬 구획·끝 ¶ 변경이 가는 중인 스토리의 상태는 미루고 ack의 새 상태를 쓴다.
  - 이 미루기는 무작위 시험이 찾았다: 처음에는 끝 ¶ 맵 변경을 바로 적용해, 아직 보내지 않은 로컬 변경을 덮어 갈라졌다 (16시드 중 3).
- **저장**:
  - 정본 JSON은 `stories.<ID>`(비지 않은 스토리, 유령 ¶ 속성은 마지막 문단 `p`)다 (`quireFromDocument`/`documentFromQuire`).
  - 새 판 압축 `compactDocument`: 스토리는 가벼운 모양으로, 끝 ¶는 맵으로 쓴다.
  - `.quire`, 서버 JSON·압축·올리기, 자산 찾기는 모든 스토리를 본다.
  - 재기반은 본문과 스토리마다 텍스트 차이 → 서식 차이다.

## 14. 2-11 결과: 표

### 구현

- **표 레코드** (`@quire/model` `tables.ts`, `Document`):
  - 레코드는 행·열 ID 목록과 맵 `gone`·`w`(열 너비)·`span`·`ra`·`ca`·`attrs`로 되어 있다.
  - 행·열은 넣기만 하고, 지우기는 지운 표시다 (스파이크 T8). 넣기의 실행 취소도 지운 표시다.
  - 셀 스토리 ID는 `<표>|<행>|<열>`이다 (T9). 셀은 미리 만들지 않는다.
  - 병합은 왼쪽 위 셀 → 덮는 행·열 ID 목록이다. 덮인 셀의 글은 옮기지 않는다.
  - `normalizeTable`이 화면 격자를 만든다:
    - 지운 행·열을 뺀다.
    - 병합은 남은 행·열 가운데 가장 먼 것까지 늘린다.
    - 겹치면 행 우선 순서로 앞의 병합이 이긴다.
  - 본문에는 표 문단 `[표 원소][¶]`가 있다. 표 원소는 `kind: 'table'`, `table: <ID>`인 개체 글자다.
  - 레코드 연산의 실행 취소는 `{ type: 'tableMap', before, after }`다.
- **동기화**:
  - Loro 이름은 `<표>.rows`·`<표>.cols`(MovableList)와 `<표>.gone` 등의 맵이다.
  - 브리지는 컨테이너 ID로 표를 찾아 레코드를 통째로 다시 읽는다.
  - Worker는 init·원격 항목·ack에 레코드를 통째로 싣는다.
  - 메인은 그 표의 로컬 변경이 가는 중이면 원격 레코드를 미룬다 (끝 ¶ 맵과 같은 방식).
  - 새 판 압축과 재기반은 레코드를 옮긴다.
- **레이아웃** (`@quire/layout`):
  - `ParaFormat.table`(표 폭, 행 높이)이 있으면 표 문단은 줄 대신 행을 놓는다. 쪽은 행 사이에서만 나눈다.
  - `TableLayouter`는 셀마다 쪽 하나(높이 무한)로 조판한 `PagedLayout`을 둔다.
    - 행 높이 = max(최소 높이, 한 행짜리 셀의 내용 + 여백)이다.
    - 병합 셀은 모자란 높이를 마지막 행에 더한다.
    - 덮인 셀의 글은 주인 셀 아래에 이어진다.
  - 셀 레이아웃의 좌표는 **원점**(`PageSetup.originX/Y`, `setOrigin`)으로 본문과 같은 문서 좌표다. 그래서 캐럿·hit-test·선택 그리기를 본문 코드 그대로 쓴다.
  - 바뀌지 않은 셀은 스토리 판(`Doc.version`)이 같으면 다시 보지 않는다.
- **편집기**:
  - `Editor.document`(Document)가 있고, `doc`·`layout`은 **편집 중인 스토리**를 가리킨다 (본문, 또는 셀). 쪽은 `bodyLayout`이 맡는다.
  - 셀의 연산은 `Document.tag`로 감싸 기록한다. `Selection.story`가 있어 실행 취소가 그 셀로 돌아간다.
  - 셀 입력이 있으면 표 문단을 `touchParagraph`해서 다시 조판한다.
  - 서식 번호의 뜻은 스토리마다 다르다. 그래서 그리기·서식 캐시는 스토리마다 따로 두고, 셀 문단 레이아웃 캐시 키에 스토리 번호를 넣는다.
  - 셀로 들어가고 나오기:
    - 누르기, Tab·Shift+Tab (마지막 셀에서 Tab은 행 더하기), 화살표 (셀 위아래·좌우 끝에서 이웃 셀이나 표 밖).
    - 본문 캐럿이 표 문단에 오면 표로 들어간다.
    - 표 뒤 문단 처음의 Backspace와 표 앞 문단 끝의 Delete는 표와 합치지 않고 표로 들어간다.
  - **셀 범위 선택**은 Shift+누르기나 다른 셀로 끌기다. Delete로 내용을 지운다.
  - 명령: `insertTable`, `tableAddRow/Col`, `tableDelete('row'|'col')`(다 지우면 표 지우기), `tableMerge`·`tableUnmerge`, `tableCellFill`, `tableSetColWidth`, `deleteTable`.
  - 미러는 `table`/`tr`/`td`이고, 병합은 `rowspan`·`colspan`이다.
  - 플레이그라운드에는 표 넣기와 셀 안에서만 보이는 표 도구가 있다.
- **정본 JSON**:
  - 본문 블록은 `{ "table": { "cols": [너비…], "rows": [ { "cells": [ { "story", "span"?, "fill"? } ], "h"? } ] } }`이다. 덮인 칸에는 셀이 없다.

  - 덮인 셀의 글은 주인 셀 스토리 뒤에 붙인다. 지운 행·열과 행·열 ID는 쓰지 않는다. 열면 새 ID를 만든다.

### 남은 것 (3단계)

- 행 쪼개기: 쪽보다 큰 행은 넘친다. 여러 행 병합 셀이 쪽을 넘으면 첫 행 자리에 넘쳐 그린다.
- 제목 행 반복(`header`은 저장만 한다), 자동 열 너비, 열 너비 끌기(지금은 명령 `tableSetColWidth`만).
- 셀 안 떠 있는 개체는 인라인으로 놓는다. 셀 안 목록 정의는 셀 스토리에 있어 다른 피어와 공유되지 않는다.
- 덮인 셀의 글은 보이지만 따로 편집할 수 없다 (나누면 다시 편집할 수 있다).
- 프레즌스는 셀 안에서도 표 원소 자리를 알린다 (셀 캐럿은 다른 피어에게 보이지 않는다).
- 스타일 정의가 바뀌어도 판이 같은 셀은 다시 조판하지 않는다 (다음 문서 열기·글꼴 바꾸기에서 맞춰진다).

## 15. 2-12 결과: 다중 커서

### 구현

- **캐럿**: 첫 캐럿은 지금의 선택(`sel`), 다른 캐럿은 `extras`(원소 위치 `Position`)다. 같은 스토리 안에서만 (본문, 또는 편집 중인 셀).
  - 더하기: Alt+누르기, Ctrl+Alt+↑/↓ (가장 위·아래 캐럿의 위·아래 줄, 첫 캐럿의 x). Esc는 첫 캐럿만 남긴다. 그냥 누르기·선택 바꾸기도 그렇다.
  - 겹치거나 같은 자리의 캐럿은 합친다 (첫 캐럿이 남는다). 상한 1,000개.
- **편집** (`editAll`): 캐럿을 뒤(큰 오프셋)부터 편집해 앞 캐럿의 오프셋이 그대로 맞는다. 편집한 캐럿은 바로 원소 위치로 바꿔 들고 다닌다. 트랜잭션 하나로 기록한다.
  - 입력·붙여넣기·Enter·Tab: 모든 캐럿에 넣는다 (선택이면 바꾼다). 연속 입력은 실행 취소 한 단계로 합친다.
  - Backspace·Delete (Ctrl이면 단어): 캐럿마다. 문단 경계를 넘는 지우기도 된다. 레이아웃은 편집 중에 낡으므로 글자 경계는 문단 텍스트에서 바로 구한다.
  - 서식 (Ctrl+B 등, 크기·색): 비지 않은 선택마다. 문단 속성(정렬·스타일): 모든 캐럿이 걸친 문단.
  - 이동 (←/→, Ctrl+←/→, ↑/↓, Home/End, Shift면 늘리기): 캐럿마다.
  - 복사·잘라내기: 선택들을 문서 순서로 줄로 잇는다.
- **실행 취소**: `Selection.more`에 다른 캐럿을 담아, 되돌리면 캐럿들도 돌아온다.
- **한글 조합**: 조합은 첫 캐럿(입력 층이 놓인 곳)에서만 한다. 다른 캐럿 자리에는 조합 중 문자열을 흐리게 미리 그린다. 확정하면 모든 캐럿에 넣는다. 조합 시작에 선택이 있으면 모든 선택을 먼저 지운다.
- **`Doc.batch`**: 여러 곳 편집 중에는 문단 시작 옮기기(문단 수만큼)를 미루고 끝에 한 번 한다. 미룬 구간은 늘 지금 편집보다 뒤라, 문단 찾기는 그 앞에서 끝난다. 이것이 없으면 10만 문단에서 캐럿 100개 입력이 31 ms였다.
- 그리기: 다른 캐럿은 캔버스에 그린다 (첫 캐럿은 DOM 캐럿). 선택 범위는 모두 칠한다.
- 프레즌스는 첫 캐럿만 보낸다.

### 남은 것

- 실제 IME로 한글 조합을 다중 커서에서 확인하는 것은 체크리스트에 넣을 것 (자동 입력은 조합 이벤트를 만들지 않는다).
- 다른 스토리(셀)에 걸친 캐럿, 셀 범위와 다중 커서를 함께 쓰는 것은 없다.
- 보류 서식(선택 없이 Ctrl+B)은 첫 캐럿에만 걸린다.
- 다른 사용자의 여러 캐럿 보이기 (O-25)는 열린 질문 그대로다.
