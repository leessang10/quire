- 상태: 초안

### 기준 문서 세트 (06 §4 "범위 폭발" 완화, 02 O-7)

3단계는 끝이 흐려지기 쉽다. 완료를 "기능 목록"이 아니라 **기준 문서 세트의 기대값**으로 판단한다.

- `fixtures/docs/`에 정본 JSON으로 둔다: 보고서(제목·목록·표·각주), 논문(2단·각주 많음·긴 표), 소식지(구역마다 단 수가 다름·어울림 그림), 서식 문서(구역 3개·가로 쪽·머리말 홀짝).
- 문서마다 기대값 파일: 쪽 수, 쪽마다 첫 문단·첫 줄과 각주 번호, 단 나눔 위치. 사람이 한 번 보고 고정한다.
- 시험은 엔진 글꼴로 조판해 기대값과 비교하고, 레이아웃 지문(02 §2)을 Node와 Chromium에서 같게 유지한다.
- 한글 문장 세트(G7)도 같은 방식: 금칙·문장부호·영문 섞인 문장 200개와 기대 줄 나눔.

## 2. 레이아웃의 바탕: 프레임 열

지금 `PagedLayout`은 쪽이 모두 같고 본문 영역이 하나다(쪽 번호, y). 3단계의 기능은 거의 모두 **본문을 흘려 넣을 영역의 모양**을 바꾼다. 그래서 먼저 배치의 바탕을 바꾼다.

```ts
/** 본문을 흘려 넣는 직사각형 하나: 단 하나, 또는 표 행 조각 (문서 좌표) */
interface Frame {
  page: number;
  /** 같은 쪽에서 몇 번째 단 */
  column: number;
  x: number;
  top: number;
  width: number;
  /** 각주 영역을 빼기 전 높이 */
  height: number;
  /** 이 프레임이 속한 구역 */
  section: string;
}

interface FrameSource {
  /** k번째 프레임 (필요할 때 만든다). 앞 프레임과 구역 나눔으로 정해진다 */
  frame(k: number): Frame;
  /** 구역이 바뀌는 문단: 그 구역의 첫 프레임 번호 */
  startSection(k: number, section: SectionProps, kind: SectionBreak): number;
}
```

- 배치 상태는 `(프레임 번호, 프레임 안 y, 각주 상태)`다 (지금의 `(쪽, y)`). 수렴 판단은 이 상태와 배제 영역 서명(2-9)을 비교한다.
- 문단 레이아웃(줄 나누기)은 **줄 폭**으로 캐시한다. 한 구역 안의 단은 폭이 같으므로 문단은 구역 경계를 넘지 않는 한 한 번 나눈다. 구역이 바뀌는 곳은 늘 문단 경계다.
- 프레임 높이는 구역 설정(용지·여백·머리말 높이)과 단으로 정해지고, 배치 중에 각주가 줄인다 (§6).
- 표 셀 레이아웃(11 §14의 `TableLayouter`)도 같은 틀을 쓴다: 셀 내용의 프레임 = 행 조각들 (§8).
- 쪽 크기가 쪽마다 다르므로 `pageTop(page)`는 앞 쪽들의 높이 합이다. 레이아웃이 쪽 상자 목록(`pages: { top, width, height, section }`)을 낸다. 편집기는 쪽을 이 목록대로 그린다 (지금은 A4 상수).
- 3-1은 이 바꿈만 한다: 기능은 그대로이고 모든 시험·지문이 같아야 한다.

## 3. 구역 (G1)

### 3.1 모델

- 구역의 끝은 **그 구역 마지막 문단 ¶의 문단 속성** `section: <구역 ID>`다. 마지막 구역은 표시가 없고 문서 설정의 기본 구역을 쓴다. 01 §2의 구역 표식 `§`를 새 원소로 두지 않는 이유: 문단 속성은 이미 동기화·실행 취소·정본이 있고(10), 구역 나눔은 늘 문단 경계에 있다.
- 구역 설정은 문서의 구역 맵 `sections: ID → SectionProps`:

```ts
interface SectionProps {
  /** 1/1000pt. 방향은 width > height로 나타낸다 */
  page: { width: number; height: number; margin: [top: number, right: number, bottom: number, left: number] };
  /** 이 구역이 어떻게 시작하는가 */
  start: 'nextPage' | 'continuous' | 'evenPage' | 'oddPage';
  columns?: { count: number; gap: number; separator?: boolean };
  /** 머리말·꼬리말 스토리 (§5). first는 titlePage일 때만 */
  header?: { default?: string; first?: string; even?: string };
  footer?: { default?: string; first?: string; even?: string };
  titlePage?: boolean;
  /** 머리말·꼬리말과 용지 끝 사이 */
  headerDistance?: number;
  footerDistance?: number;
  /** 쪽 번호: 이 구역에서 다시 시작, 모양 */
  pageNumber?: { start?: number; format?: 'decimal' | 'roman' | 'hangul' };
}
```

- 짝·홀수 쪽 시작이 빈 쪽을 만들면 그 쪽은 머리말·꼬리말만 그린다.
- 편집: 구역 나누기(Ctrl+Alt+Enter: 다음 쪽), 쪽 설정 대화상자(용지 A4·B5·Letter·사용자, 방향, 여백, 시작 방식). 구역 나눔을 지우면(그 ¶의 `section` 속성 해제, 또는 문단 합치기로 ¶가 사라짐) 앞 구역이 뒤 구역에 합쳐진다: **뒤 구역 설정이 남는다** (Word와 같다).
- 쪽 나눔(Ctrl+Enter)은 다음 문단의 `pageBreakBefore`다 (구역은 그대로).

### 3.2 동기화·저장

- Loro: 구역마다 맵 `sec.<ID>` (키마다 LWW). 정의 맵(스타일·목록)처럼 Worker가 바뀐 구역을 통째로 싣는다.
- 두 사람이 동시에 같은 구역 설정의 다른 키를 바꾸면 둘 다 반영된다. 같은 키는 나중 것.
- 구역 나눔 ¶를 지우는 동안 다른 사람이 그 구역 설정을 바꾸면 설정은 남지만 쓰이지 않는다 (되돌리면 다시 쓰인다).
- 정본 JSON: `sections` 배열(07 §4)은 문서 순서의 구역들이다. 마지막 구역이 기본 구역이다. 문단의 `p.section`은 구역 ID를 가리킨다. 쓰이지 않는 구역은 저장하지 않는다.

### 3.3 레이아웃

- 문단을 놓기 전에 그 문단의 구역을 안다: 앞 문단 ¶에 `section`이 있으면 다음 구역이 시작된다. 구역 차례는 `section` 속성이 있는 ¶들의 순서로 정해진다 (증분: 그 목록은 문단 속성이 바뀔 때만 바뀐다).
- `continuous`: 같은 쪽에서 이어서 시작한다. 단 수가 바뀌면 쪽을 위·아래 띠로 나눈다 (§7.2).
- 쪽 번호 매기기는 조립이 끝난 쪽 목록에서 계산한다 (본문 배치와 무관, §5.3).

## 4. 쪽 나눔 제어 (G2)

10 §2.2의 `pageBreakBefore`·`keepWithNext`·`keepTogether`(지금은 저장만)와 문서 설정 `widowControl`(기본 2줄)을 조판한다.

| 규칙 | 배치 |
|---|---|
| `pageBreakBefore` | 문단을 새 프레임 맨 위에 놓는다 (다단이면 다음 쪽 첫 단. `columnBreakBefore`는 다음 단) |
| `keepTogether` | 문단이 지금 프레임에 다 들어가지 않으면 다음 프레임으로 (프레임보다 크면 무시) |
| `keepWithNext` | 이 문단과 다음 문단의 **첫 두 줄**(다음도 keepWithNext면 그 사슬 전체 + 사슬 다음 문단의 첫 두 줄)이 같은 프레임에 들어가야 한다. 안 되면 사슬 첫 문단부터 다음 프레임으로. 사슬이 프레임보다 크면 무시 |
| 고아 줄 | 문단을 나눌 때 프레임 끝에 1줄만 남으면 문단 전체를 다음 프레임으로 |
| 과부 줄 | 다음 프레임에 1줄만 넘어가면 앞 프레임에서 한 줄 더 넘긴다 (앞에 2줄 이상 남을 때) |

- 모두 **앞에서 뒤로 한 번** 놓는 규칙이다. `keepWithNext`는 사슬 끝까지 미리 보고(문단 레이아웃은 캐시에 있음) 정한다. 되돌아가 다시 놓는 백트래킹이 없어 증분 조립(02 §7)의 수렴 판단이 그대로다.
- 미리 보기 때문에 문단 k의 위치가 문단 k+1…의 내용에 기댄다. 증분 조립에서 문단이 바뀌면 그 문단이 속한 `keepWithNext` 사슬의 첫 문단부터 다시 놓는다.
- 기본 스타일 제목 1–3은 이미 `keepWithNext`다 (10, 기본 스타일). 3-3부터 제목이 쪽 끝에 홀로 남지 않는다.

## 5. 머리말·꼬리말과 필드 (G3)

### 5.1 모델

- 머리말·꼬리말은 가벼운 스토리(11 §13)다. ID는 `hdr|<구역>|<default|first|even>`, `ftr|…`. 구역 설정이 쓰는 스토리를 가리킨다. 구역 설정에 없으면 **앞 구역의 것을 이어 쓴다** (Word의 "이전과 연결").
- 필드는 인라인 개체(11 §2.1)다: `kind: 'field'`, `field: 'page' | 'pages' | 'sectionPages' | 'date'`. 값은 저장하지 않고 그릴 때 정한다.
- 필드는 3단계에서 **머리말·꼬리말에만** 넣을 수 있다. 본문의 쪽 번호 필드는 쪽 나눔과 순환을 만든다 (O-29).

### 5.2 레이아웃

- 머리말 높이는 구역·종류(default/first/even)마다 **한 번** 잰다. 필드는 자리표시 값(쪽 번호 `999`, 전체 쪽 수 `999`)의 폭으로 잰다. 그래서 본문 프레임은 쪽 번호와 무관하다.
- 본문 프레임 위 = max(위 여백, `headerDistance` + 머리말 높이). 꼬리말도 같다 (아래). 머리말이 여백보다 크면 본문을 민다.
- 그릴 때는 쪽마다 필드에 실제 값을 넣어 그 쪽의 머리말을 조판한다(작은 문단 몇 개, 캐시 키에 필드 값). 필드 폭이 자리표시와 달라도 줄 수가 바뀌면 높이가 달라질 수 있다: 이때는 쟀던 높이 안에서 잘라 그리고 진단에 적는다.

### 5.3 쪽 번호

- 쪽 번호는 조립된 쪽 목록에서 정해진다: 구역의 `pageNumber.start`부터, 짝·홀수 시작으로 넣은 빈 쪽도 센다.
- 전체 쪽 수가 바뀌어도(문서 끝에 쪽이 늘어남) 본문은 다시 조립하지 않는다. 보이는 쪽의 머리말만 다시 그린다.
- 아직 백그라운드 조립 중이면 전체 쪽 수는 추정값(지금의 `pageCount`)이고 흐리게 그린다.

### 5.4 편집

- 쪽의 머리말·꼬리말 영역을 두 번 누르면 그 스토리를 편집한다. 표 셀과 같은 "편집 중인 스토리 바꾸기"(11 §14)를 일반화한다: `ActiveStory = { story, kind: 'cell' | 'header' | 'footer' | 'footnote', … }`.
- 본문은 흐리게 그린다. Esc나 본문 두 번 누르기로 나온다.
- 같은 머리말 스토리가 여러 쪽에 그려지므로 캐럿은 누른 그 쪽에만 그린다.
- 명령: 쪽 번호 넣기, 전체 쪽 수 넣기, 첫 쪽 다르게, 짝·홀 다르게, 이전과 연결 끊기(앞 구역 스토리를 복사해 새 스토리).

## 6. 각주 (G4)

### 6.1 모델

- 각주 참조는 인라인 개체다: `kind: 'note'`, `id`. 각주 내용은 가벼운 스토리 `fn|<참조 개체 id>`다 (셀처럼 ID에서 정해짐: 두 피어가 동시에 처음 열어도 하나).
- 번호는 저장하지 않는다: 본문의 참조 개체 순서로 1, 2, 3 … (목록 번호처럼 파생 값, 10 §2.4). 구역마다 다시 시작은 3단계 밖.
- 참조를 지우면 각주 스토리는 남는다 (묘비처럼). 되돌리면 그대로 돌아온다. 정본에는 쓰이는 각주만 저장한다.
- 참조를 복사해 붙이면 새 개체 id + 각주 스토리 복사.

### 6.2 레이아웃

- 참조 글자의 폭 = 번호 글자(위 첨자)의 폭이다. 앞에 각주를 넣으면 뒤 번호가 모두 바뀐다: 9 → 10에서 폭이 바뀌므로 번호가 바뀐 참조가 있는 문단은 다시 나눈다 (목록 번호의 `listEpoch`와 같은 방식, 바뀐 번호의 자릿수가 같으면 다시 나누지 않는다).
- 각주 내용은 셀처럼 스토리마다 작은 레이아웃이다 (각주 영역 폭).
- **배치**: 줄을 프레임에 놓을 때, 그 줄의 참조들의 각주 높이를 그 프레임의 각주 영역에 더한다. 프레임에 남은 높이 = 프레임 높이 − 본문 y − 각주 영역(구분선 포함). 줄 + 새 각주가 들어가지 않으면 그 줄을 다음 프레임으로 넘긴다.
- 각주 하나가 빈 프레임의 절반보다 크면 들어가는 만큼만 놓고 나머지를 다음 프레임 각주 영역 맨 앞에 이어 쓴다 (이어 쓰기 구분선). 이어 쓸 각주는 배치 상태(§2)에 들어간다.
- 다단: 각주는 **참조가 있는 단 아래**에 놓는다 (O-26). 그래서 단마다 각주 영역이 따로이고, 앞 단의 높이가 뒤 단의 각주로 바뀌는 순환이 없다.
- 증분: 각주 내용이 바뀌면 그 각주의 참조가 있는 문단을 바뀐 것으로 본다 (표 셀 입력이 표 문단을 바꾸는 것과 같다, 11 §14). 각주 높이가 같으면 참조 문단의 위치만 보고 수렴한다.

### 6.3 편집

- 각주 넣기(Ctrl+Alt+F): 캐럿에 참조를 넣고 그 각주 스토리를 편집한다.
- 쪽 아래 각주를 누르면 그 각주를 편집한다. 각주 번호를 두 번 누르면 본문 참조로 간다.
- 미러: 참조는 `<a role="doc-noteref">`, 각주 영역은 `<aside role="doc-footnote">`에 번호와 내용 (04 §3).

## 7. 다단 (G5)

### 7.1 단

- 구역 설정 `columns`: 같은 폭의 단 `count`개, 간격 `gap`, 구분선. 프레임 열은 쪽마다 단 수만큼 프레임을 낸다.
- 단 나눔: 문단 속성 `columnBreakBefore` (Ctrl+Shift+Enter).
- 떠 있는 개체의 `relX: 'column'`은 지금 단이다. 단 밖으로 나가는 개체의 배제 영역은 그 쪽의 모든 단에 걸린다 (2-9의 배제 영역은 쪽마다라 그대로 된다).
- 표는 단 폭으로 놓는다 (열 너비 합이 단보다 크면 비율로 줄여 그린다, 11 §4.3).

### 7.2 이어지는 구역과 단 균형

- `continuous` 구역이 단 수를 바꾸면 쪽을 띠로 나눈다: 앞 구역 마지막 띠의 아래부터 새 구역의 프레임을 만든다.
- 앞 구역이 다단이면 마지막 띠의 **단 균형**을 맞춘다: 그 띠에 놓인 줄들을 단마다 높이가 비슷하도록 다시 나눈다. 균형은 이분 탐색(띠 높이 h에서 다 들어가는가)이다. 띠 안의 문단만 다시 놓으므로 비용은 그 띠의 크기다.
- 균형을 맞춘 띠의 높이가 바뀌면 그 뒤가 밀린다. 수렴 판단은 띠 끝 상태로 한다.
- 문서 끝 다단 구역의 마지막 쪽은 균형을 맞추지 않는다 (Word 기본과 같다, 설정으로 켬).

## 8. 표 쪽 분할 (G6)

11 §4.3의 "행 사이에서만 쪽 나눔"을 넓힌다.

- 행 속성 `cantSplit`(행 나누지 않음, 기본 꺼짐)과 `header`(제목 행, 11 §2.4에 저장만 있음).
- 행이 프레임의 남은 높이보다 크고 `cantSplit`이 아니면 **행을 쪼갠다**: 셀마다 내용 줄을 남은 높이(여백 뺀 것)까지 첫 조각에, 나머지를 다음 프레임의 조각에 놓는다. 줄은 쪼개지 않는다 (줄 하나가 조각보다 크면 그 줄은 넘친다).
- 셀 레이아웃의 프레임 = 행 조각들이다 (§2). 셀 레이아웃은 쪽 하나(높이 무한)로 한 번 나누고, 조각 경계에서 줄을 다음 조각으로 옮기는 **y 대응**만 다시 계산한다 (줄 나누기는 폭에만 기댄다).
- 행 조각 높이 = 그 조각 셀들의 가장 큰 내용 높이 + 여백. 여러 행 병합 셀은 걸친 행 조각들에 이어 흐른다.
- 제목 행: 표가 다음 프레임으로 이어지면 `header` 행들(표 맨 위에서 이어진 것)을 그 프레임 맨 위에 다시 그린다. 다시 그린 제목 행은 같은 셀 레이아웃을 다른 원점으로 그린다 (편집은 원래 자리에서만).
- 쪽보다 큰 `cantSplit` 행은 쪼갠다 (넘치게 두지 않는다) 그리고 진단에 적는다.

## 9. 한글 조판 (G7)

02 §4의 줄바꿈·양쪽 정렬 규칙을 문서 설정으로 완성한다.

### 9.1 줄바꿈

- 문단 속성 `koreanBreak: 'word' | 'char'` (기본 word, 문서 설정 기본값). `char`는 한글 음절 사이 어디서나 끊는다 (한글 프로그램의 "글자 단위").
- 영문·숫자는 늘 단어 단위다 (UAX #14). URL처럼 긴 단어는 줄보다 길면 글자 단위.
- 금칙: 문서 설정 `kinsoku: { noStart: string; noEnd: string }`. 기본값은 Word·한글 프로그램의 한국어 기본 목록을 참고한 초안이다 (O-30):
  - 줄 앞 금지: `!%),.:;?]}¢°’”‰′″℃、。〉》」』】〕〗〙〛ﾠ` 와 한글 조판 문장부호 `…‥·`.
  - 줄 끝 금지: `$([{£¥‘“〈《「『【〔〖〘〚＄`.
- 처리 방식: 끊을 곳이 금칙이면 **앞 글자를 다음 줄로 넘긴다**(밀어내기). 넘기면 줄이 너무 짧아질 때(양쪽 정렬의 늘림 한도를 넘음)만 문장부호를 줄 끝 여백에 걸친다(매달기, 9.3).

### 9.2 양쪽 정렬

지금(10 §4): 어간(공백)에 나누고, 공백이 없으면 글자 사이에 글자당 0.3em까지.

- 늘림 순서: ① 어간을 글자 크기의 0.5em까지 ② 남으면 글자 사이를 0.1em까지 ③ 그래도 남으면 어간에 모두.
- 줄임: 어간을 0.2em까지 줄여 한 어절을 더 넣을 수 있으면 넣는다 (한글 프로그램의 "줄 나눔 기준 최소 공백"). 줄임은 줄바꿈 단계에서 정한다: 줄 폭 + 어간 수 × 0.05em까지 들어가는 줄을 허용.
- 마지막 줄, 강제 줄바꿈 앞 줄은 늘리지 않는다.
- 문단 단위 최적 줄바꿈(Knuth–Plass)은 3단계에서 하지 않는다 (O-31). 위 규칙은 한 줄씩(탐욕) 정해 증분·결정성이 지금과 같다.

### 9.3 문장부호

- 매달기(문장부호 걸침): 줄 끝의 `,.、。` 하나는 오른쪽 여백에 걸칠 수 있다 (문단 설정, 기본 꺼짐).
- 여는·닫는 괄호와 따옴표가 이어질 때 반각으로 줄이기는 3단계 밖이다.

## 13. 3-1 결과: 프레임 열과 기준 문서 세트

### 구현

- **프레임 열** (`@quire/layout` `document.ts`):
  - `Frame { page, column, x, top, width, height }`, `PageBox`, `FrameSource { frame(k), page(p), pageAt(y), height(n) }`.
  - `UniformFrames`: 2단계까지의 모양 (프레임 k = 쪽 k, 본문 영역 하나). 프레임을 캐시하고 원점(표 셀)이 바뀌면 비운다.
  - `PagedLayout(…, frames = new UniformFrames(setup))`. 배치 상태 `(쪽, y)`는 이제 `(프레임 번호, 프레임 안 y)`다 (`PlacedPara.pageBefore·pageAfter`, 떠 있는 개체 배제 영역의 "쪽"도 프레임 번호).
  - 본문 높이·줄 x·줄 y·떠 있는 개체의 쪽 기준·표 행 x는 모두 그 줄이 놓인 프레임에서 읽는다. `PlacedLine.page`는 쪽 번호(`frame.page`)다.
  - 계산 순서를 그대로 두어(위 = 쪽 위 + 여백, 그다음 + y) 부동소수점 비트까지 같다: 결정성 지문 4개가 바뀌지 않았다.
  - `pageCount`는 마지막 프레임의 쪽, `totalHeight`는 `frames.height(n)`, 새 `pageBox(p)`·`pageAt(y)`.
- **편집기**: 쪽을 A4 상수가 아니라 `layout.pageBox(p)`로 그린다 (구역마다 쪽 크기가 다를 수 있다).
- **서식 분리** (`packages/editor/src/formatter.ts`, DOM 없음): 서식 번호 → 런 영향·그리기 정보, 문단 상자, 목록 번호, 개체 크기, 표 문단 → 행 높이를 `Formatter`로 옮겼다. 편집기와 Node 시험이 같은 서식으로 조판한다 (02 R6, 나중에 Worker·PDF). 편집기 쪽 설정도 `defaultPageSetup()` 하나다.
- **기준 문서 세트** (`fixtures/docs/`, `packages/editor/src/reference.test.ts`):
  - 문서마다 정본 JSON과 기대값 `*.expected.json`(쪽 수, 쪽마다 첫 줄: 문단·줄 번호·앞 글자, 모든 줄과 셀 줄의 레이아웃 지문).
