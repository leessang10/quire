# 10. 서식 (2단계 1부)

- 상태: 초안
- 해결 대상: L2(서식), L4(문단 조판 일부), 01 O-5(서식 확장 규칙)
- 근거: 01 §4(서식과 범위 레이어), 02 §4–5, 05 §2·§4, 07 §4, 09, ADR-0002·0003
- 범위: **글자 서식, 문단 서식, 스타일, 목록**. 이미지·어울림·표·다중 커서(2단계 2부)는 11에서 다룬다.

## 1. 목표

- 굵게·기울임·밑줄·취소선·글꼴·크기·색·형광펜·링크·위/아래 첨자를 글자 범위에 건다.
- 문단에 정렬, 들여쓰기(왼·오른·첫 줄), 앞뒤 간격, 줄 간격, 스타일(제목 1–3 등), 목록(글머리·번호, 수준)을 건다.
- 서식이 들어와도 지금의 성질을 잃지 않는다.
  - 키 입력 p95 16 ms(1,000쪽), 증분 조판, 결정적 쪽 나눔(02 R1).
  - 동시 편집 수렴, 사용자별 실행 취소, 오프라인 재기반(09).
  - 정본 JSON 왕복(07, ADR-0004).

## 2. 모델

01 §4의 구분을 그대로 쓴다: **글자 서식은 원소 열 위의 구간, 문단 서식은 ¶ 원소의 속성.** 주석(댓글 등)은 이 문서 범위 밖이다.

### 2.1 글자 서식: 서식 묶음 번호

글자마다 서식 객체를 들면 1,000쪽 문서(130만 글자)에서 메모리가 감당되지 않는다. **서식 묶음(MarkSet)을 한 번만 만들고 번호로 가리킨다.**

```ts
interface MarkSet {
  bold?: true; italic?: true; underline?: true; strike?: true;
  font?: string;          // 글꼴 이름 (문서 글꼴 목록의 키)
  size?: number;          // 1/1000pt
  color?: string;         // #rrggbb
  highlight?: string;
  link?: string;
  script?: 'sup' | 'sub';
}
```

- Doc에 `marks: MarkSet[]` 표를 둔다. 0번은 빈 묶음이다. 같은 내용의 묶음은 같은 번호를 쓴다(키 정렬 후 문자열로 찾기).
- 청크마다 `fmt: Uint16Array(CAP)`를 더한다. 원소당 2바이트로, 지금 글자당 약 13바이트에 2바이트가 는다.
- 묶음 수 상한은 65,535개다. 넘으면 쓰지 않는 번호를 모아 다시 쓴다(저장 시 압축).
- 화면 질의: `marksAt(offset)`, `runs(from, to)`(같은 묶음이 이어진 구간). 레이아웃은 문단 단위로 묶음 번호 열을 받는다(§4).

### 2.2 문단 서식: ¶의 속성

```ts
interface ParaAttrs {
  style?: string;                       // 문단 스타일 이름 (§2.3)
  align?: 'left' | 'center' | 'right' | 'justify';
  indent?: { left?: number; right?: number; first?: number };   // 1/1000pt, first는 음수면 내어쓰기
  space?: { before?: number; after?: number };
  line?: { rule: 'multiple' | 'exact' | 'atLeast'; value: number };
  list?: { id: string; level: number };
  keepWithNext?: true; keepTogether?: true; pageBreakBefore?: true;   // 3단계에서 조판
}
```

- Doc은 ¶ 원소 ID → `ParaAttrs`의 맵을 둔다. 문단 ID는 이미 ¶의 ID다(01 §3.1). 속성 없는 문단은 맵에 없다.
- **문단 나누기(Enter)**: 새 ¶가 앞 문단이 된다(01 §3.1: 뒤쪽이 기존 ID). 새 ¶에 지금 문단의 속성을 복사한다. 예외: 제목에서 문단 끝 Enter는 다음 문단을 본문 스타일로 만든다(스타일의 `next`).
- **문단 합치기**: 앞 문단의 ¶가 지워지고, 합친 문단은 뒤 ¶의 속성을 가진다(¶가 속성을 소유). 사용자는 보통 앞 문단 서식이 남기를 기대한다(Google Docs, 최근 Word). 그래서 편집기의 합치기 명령은 **같은 트랜잭션에서 앞 문단 속성을 뒤 ¶로 복사**한다. 모델 규칙은 단순하게, 사용 경험은 명령에서 맞춘다.

### 2.3 스타일

```ts
interface Style {
  name: string; basedOn?: string; next?: string;
  kind: 'paragraph' | 'character';
  para?: ParaAttrs;      // 문단 스타일만
  marks?: MarkSet;       // 문단 스타일의 기본 글자 서식, 또는 글자 스타일
}
```

- 실제 서식 = 문단 스타일 사슬(`basedOn`)의 값 → 문단 직접 속성 → 글자 스타일 → 글자 직접 서식 순으로 덮어쓴 것.
- 레이아웃에는 **풀어 쓴 값**만 넘긴다. 풀이는 (스타일 판, 문단 속성, 묶음 번호)로 캐시한다. 스타일을 고치면 판이 올라가 그 스타일을 쓰는 문단이 다시 조판된다.
- 기본 스타일: 본문, 제목 1–3, 목록 문단, 인용. 문서 설정(07 §4 `styles`)에 저장한다.

### 2.4 목록

- 문단 속성 `list: {id, level}`과 문서 설정의 목록 정의(`lists[id].levels[n]`: 글머리 기호 또는 번호 형식 `1.` `가.` `①` `i)`, 들여쓰기)로 표현한다. 중첩 노드는 없다(01 §2).
- 번호는 **파생 값**이다. 화면 순서(구획 순서 반영)로 같은 `id`의 문단을 세어 수준별 번호를 매긴다.
  - 문단 목록과 함께 증분 유지하되, 목록 문단이 바뀌면 그 목록의 뒤쪽만 다시 센다.
  - 번호는 문서에 저장하지 않으므로 동시 편집으로 어긋나지 않는다.
- Tab / Shift+Tab: 목록 문단에서 수준 ±1. 빈 목록 문단에서 Enter: 목록을 끝낸다(수준 0이면 목록 해제).

### 2.5 연산과 변경 기록

01 §5의 `format`, `setAttrs`를 구현한다.

| 연산 | 내용 | 역연산 |
|---|---|---|
| `{ type: 'format', ids, key, before[], after }` | ids 원소의 서식 키 하나를 after로 (undefined = 해제) | 원소별 before로 되돌림 (05 §4: 그사이 다른 사용자가 같은 키를 바꿨으면 그 원소는 되돌리지 않음) |
| `{ type: 'para', id, key, before, after }` | ¶ 하나의 문단 속성 키 하나 | before로 |
| `{ type: 'style', name, before, after }` | 스타일 정의 | before로 |

Doc의 변경 기록(RawChange, 09 §4)에 둘을 더한다 (UTF-16 위치).

```ts
| { kind: 'mark'; at: number; len: number; key: string; value: unknown }   // value null = 해제
| { kind: 'para'; at: number; key: string; value: unknown }                // at = ¶의 위치
```

삽입 기록(`insert`)에는 들어간 글자의 서식(`marks`)을 함께 싣는다. 받는 쪽이 따로 `mark`를 기다리지 않고 한 번에 같은 상태가 되게 하기 위해서다.

### 2.6 입력할 때 서식 이어받기 (01 O-5)

| 키 | 구간 끝에 입력하면 | 구간 앞에 입력하면 |
|---|---|---|
| bold, italic, underline, strike, font, size, color, highlight, script | 이어받음 | 이어받지 않음 |
| link | 이어받지 않음 | 이어받지 않음 |

- 이것이 CRDT 마크의 `expand` 규칙과 같아야 한다(§3). 로컬 입력은 "캐럿 앞 글자의 서식 중 이어받는 키"를 쓴다. 문단 첫머리에서는 캐럿 뒤 글자의 서식을 쓴다.
- **캐럿 서식**: 선택 없이 Ctrl+B를 누르면 다음 입력에만 적용되는 "보류 서식"을 캐럿에 둔다. 캐럿을 옮기면 버린다.
  - 조합 중인 한글(preedit)도 보류 서식으로 그린다.
  - 확정하면 보류 서식으로 들어간다.

## 3. 동시 편집 (Loro)

| 모델 | Loro 표현 |
|---|---|
| 글자 서식 키 | 텍스트 'body'의 마크 `key=value` (`mark`/`unmark`). `configTextStyle`로 키마다 expand: 이어받는 키는 `after`, link는 `none` |
| 문단 속성 키 | 그 문단 ¶ 글자에 마크 `p_<key>=value` (expand `none`). 구획 표식의 `seg` 마크(09 §6)와 같은 방식. Loro 마크 키에는 `:`를 쓸 수 없다 |
| 스타일·목록 정의 | 맵 `styles`, `lists` (키 = 이름·id, 값 = 정의, LWW) |

- ¶ 하나에 걸린 마크는 그 ¶가 살아 있는 동안 문단 속성이다. 같은 키를 두 피어가 동시에 바꾸면 Loro 마크 규칙(나중 Lamport가 이김)으로 수렴한다.
- 원격 델타
  - 속성만 바꾸는 `retain` + `attributes`가 서식 변경이다. 지금은 무시하는데(`deltaToOps`), `{ kind: 'format', at, len, attributes }`로 낸다.
  - `insert`의 `attributes`는 묶음 번호로 바꿔 넣는다.
  - `p_*` 키는 문단 속성으로 간다. **¶ 글자에 붙은 것만 읽는다** (동시에 ¶ 옆에 들어온 글자로 마크가 번지므로, 2-1 발견 3).
- 가상 ¶ 문단(¶ 없이 끝난 구획)에 속성을 걸 때는 그 구획 끝에 실제 ¶를 먼저 넣는다 (2-1 발견 5).
- 위치 변환(ot.ts): 서식 변경은 길이를 바꾸지 않으므로 다른 변경에 대해 범위만 옮긴다. 삽입이 서식 범위 안에 들어가면 범위가 늘어나되, 그 글자에 서식을 걸지는 expand 규칙대로 정한다(양쪽이 같은 규칙).
- 정본 JSON(07 §4)은 이미 `c: [{ t, m }]`과 `p: {…}`, `styles`를 정의한다. `canonical.ts`가 묶음을 `m`으로, ¶ 속성을 `p`로 쓰고 읽는다. 같은 서식 런은 합친다(정규화).
- **새 판 재기반(09 §9)**: 지금 diff는 화면 텍스트만 본다. 서식이 생기면 (글자, 묶음) 쌍으로 비교한다.
  - 텍스트가 같은 구간에서 서식만 다르면 `mark` 변경으로 옮긴다.
  - 문단 속성은 ¶ 순서대로 짝지어 비교한다.

## 4. 레이아웃·셰이핑·그리기

### 아이템화와 셰이핑 (02 ①–②)

- 문단의 묶음 번호 열을 레이아웃에 넘긴다. **조각(어절)을 묶음이 바뀌는 곳에서도 나눈다.** 셰이핑 단위 = (어절 안, 같은 묶음).
- 셰이퍼 키 = (글꼴 얼굴, 크기, 텍스트). 글꼴 얼굴 = (글꼴 이름, 굵기, 기울임).
  - 얼굴마다 조각 목록(manifest)이 따로 있다: `pretendard-bold` 등. 굵게는 Pretendard Bold를 같은 방식으로 조각내 넣는다.
  - Pretendard·Noto Sans KR에는 기울임꼴이 없다. 기울임은 **기울인 그리기**(렌더러에서 수평 기울임 변환)로 하고, 진행폭은 바로 선 글꼴 값을 쓴다. 한글 문서 관행(한컴, Word의 합성 기울임)과 같다.
- 진행폭 = 글꼴 단위 × 크기 ÷ upem (02 §2). 같은 글꼴 다른 크기는 셰이핑을 다시 하지 않고 크기만 곱한다(캐시를 크기와 무관하게).
- 위/아래 첨자: 크기 0.65배, 기준선 이동 ±0.33em(글꼴의 `subs`/`sups` 기능이 있으면 그것을 우선).

### 줄과 문단 (02 ④)

- **줄 높이가 줄마다 달라진다.**
  - 줄 높이 = 그 줄 런들의 (ascent + descent) 최댓값 × 줄 간격 규칙.
  - 기준선 = 최대 ascent.
  - 지금은 레이아웃 전체에 고정 `lineHeight`라, `PlacedLine`이 높이와 기준선을 갖게 바꾼다. 쪽 조립은 이미 줄 높이를 더해 간다.
- 들여쓰기: 줄 폭 = 본문 폭 − 왼쪽 − 오른쪽(첫 줄은 − first). x 시작도 그만큼 민다.
- 정렬
  - 가운데·오른쪽은 줄 x를 남는 폭만큼 옮긴다.
  - **양쪽 맞춤**은 마지막 줄을 뺀 줄에서 남는 폭을 공백(어간)에 나눠 준다. 공백이 없으면 글자 사이에 나눈다(자간, 상한 있음).
  - 이 추가 폭은 xs에 더하지 않고 줄마다 "공백 하나당 추가 폭"으로 들고 있다가, 위치 질의와 그리기에서 더한다. 그래야 문단 레이아웃 캐시(폭과 무관한 xs)를 그대로 쓴다.
- 앞뒤 간격과 문단 사이: 지금의 `paraSpacing`을 문단 속성 값으로.
- 목록: 첫 줄 앞에 번호·글머리 상자를 두고(내어쓰기 자리), 본문은 들여쓴다. 번호 문자열도 셰이핑한다.

### 그리기

- 런마다 `ctx.font`(얼굴·크기)와 색을 바꿔 `fillText`.
  - 같은 묶음 안에서는 지금처럼 어절 단위로 그린다.
  - 기울임은 `ctx.setTransform`으로 기울여 그린다.
- 밑줄·취소선·형광펜은 런 구간에 선·사각형을 그린다. 위치·두께는 글꼴 값(`post` 표의 underlinePosition/Thickness, OS/2 strikeout)을 쓰고, 없으면 크기 비례 기본값을 쓴다.
- 링크: 밑줄 + 색, Ctrl+클릭으로 연다(편집기 옵션 `onOpenLink`).
- 접근성 미러(04 §3): 제목은 `h1–h3`, 목록은 `ul/ol/li`, 굵게·기울임은 `strong/em`으로 내보낸다. 스크린리더가 구조를 읽는다.

## 9. 2-2 결과: 모델

### 구현 (`@quire/model`, `@quire/sync` canonical·ot)

- **저장**: 청크마다 `fmt: Uint16Array`. Doc에 서식 묶음 표(번호 → 얼린 `MarkSet`, 같은 내용은 같은 번호)와 (번호, 키, 값) → 번호 캐시.

- **API**: `format(from, to, key, value)`, `setParaAttr(i, key, value)`, `marksAt`, `inheritedMarks`, `markRuns`, `markSet(id)`, `internMarks`, `paraAttrs`, `paragraphRuns` / `Doc.fromParagraphRuns`.

- **변경 기록**:
  - `insert`에 `marks`를 싣는다.
  - `mark`는 저장 위치가 이어진 구간마다 하나씩 낸다. 옮긴 문단은 나뉜다.

### 같이 고친 버그: 문단 이동 뒤 실행 취소

시험을 쓰다가 `main`에도 있던 버그를 찾았다. 문단을 옮긴 뒤 입력·삭제를 되돌리면 문단 목록이 어긋나 예외가 났다(무작위 30개 중 23개). 원인과 고친 것:
1. **바뀐 구간을 ID 순서로 잡았다.** 되돌리기(`setDead`)가 첫·마지막 원소를 ID 순서로 골랐는데, 옮긴 뒤에는 화면 순서와 다르다 → 화면 위치의 최소·최대로.
2. **로컬 문서에 가상 ¶가 없었다.** 되돌리기는 구획 끝 ¶를 바로 지울 수 있다. 앞으로 하는 삭제는 꼬리 옮기기로 막는데, 되돌리기는 그 길을 타지 않는다. → 동기화 문서와 같이 가상 ¶로 보인다.
3. **화면 마지막 ¶를 지울 수 있었다** (옮긴 문단의 ¶가 맨 끝에 온 경우). → 로컬 문서에서는 되돌리기도 그 ¶는 남긴다. 빈 문단이 하나 남을 수 있지만 문서는 늘 ¶로 끝난다.

회귀 시험(`segments.test.ts`, 30개)을 더했다. 문단 이동이 섞이면 "모두 되돌리면 정확히 처음"은 보장하지 않는다(구획을 근사 자리로 되돌림, 마지막 ¶ 남김). 서식 무작위 시험은 이동이 없는 시드에서만 정확한 왕복을 본다.

## 10. 2-3 결과: 레이아웃·셰이핑·그리기

### 구현

- **모델 → 레이아웃**: `ParagraphInfo`에 `mark`(¶의 서식 번호)를 더했다. 레이아웃 입력 `ParaInput`이 `fmt`·`mark`를 받는다.
- **서식 → 레이아웃 영향** (`RunStyle`): 편집기가 서식 묶음에서 만든다. 레이아웃은 서식 키를 모르고 이 세 값만 본다.
  - `face`: 0 보통, 1 굵게.
  - `scale`: 진행폭 배율. 크기 ÷ 기본 크기이고, 첨자는 0.65배를 더 곱한다.
  - `line`: 줄 높이 배율. 첨자는 바탕 크기를 쓴다.
  - 기울임·색·밑줄·취소선·형광펜·링크는 폭에 영향이 없어 레이아웃에 들어가지 않는다.
- **조각과 셰이핑** (`layoutParagraph`):
  - 조각(어절)을 서식 번호가 바뀌는 곳에서도 나눈다.
  - 셰이퍼 캐시 키는 (얼굴, 조각)이다. 크기는 셰이핑하지 않고 진행폭에 배율을 곱한다.
  - `fmt`가 없는 문단은 서식 전과 같은 경로다. 서식 없는 지문 `5a769681`이 그대로다.
- **굵은 얼굴**:
  - 굵게는 Pretendard Bold로 셰이핑하고 그린다. `fonts/pretendard/Pretendard-Bold.otf`, v1.3.9.
  - `build-fonts.mjs`가 보통 굵기와 **같은 조각**으로 잘라 `pretendard-bold/`에 둔다. `attachBold`가 조각 이름으로 짝을 짓는다.
  - 굵은 조각은 굵은 글자가 처음 나올 때 받는다. 그동안은 대체 측정기(시스템 글꼴 굵게)로 재고, 받으면 다시 조판한다.
  - 굵은 얼굴이 없는 글꼴(Noto Sans KR 한자 등)은 보통 굵기로 재고 합성 굵게로 그린다.
- **줄 높이와 기준선**:
  - `LineBox.scale`은 줄에서 가장 큰 `line`이다. 마지막 줄은 ¶도 세고, 빈 줄은 ¶ 서식만 본다.
  - 줄 높이는 `round(lineHeight × scale)`이다. 배율 1이면 `lineHeight` 그대로라 서식 없는 쪽 나눔은 바뀌지 않는다.
  - 기준선은 줄 가운데에 그 줄 가장 큰 글자의 글꼴 상자(ascent + descent)를 세운 자리다. `PlacedLine.baseline`이고, 크기가 섞인 줄도 기준선 하나에 선다.
  - ascent·descent·밑줄·취소선 치수는 기본 글꼴의 hhea·post·OS/2 표에서 읽는다 (`ShapingFont.metrics`). 시스템 글꼴이면 캔버스 `fontBoundingBox`를 쓴다.
- **레이아웃 캐시**: 서식이 있으면 키에 서식 번호 런을 넣는다. 번호의 뜻은 문서마다 다르므로 문서를 바꾸면 캐시를 비운다 (이미 그랬다).
- **그리기** (`drawRuns`):
  - 글꼴 번호·서식 번호·공백이 바뀌는 곳마다 나눠 레이아웃 위치에 `fillText`한다. 그리기는 alphabetic 기준선을 쓴다.
  - 기울임은 기준선 기준 수평 기울임(`transform`, tan ≈ 0.21)이다. 진행폭은 바로 선 글꼴이다.
  - 형광펜은 글꼴 상자를 칠하고 선택 영역 아래에 그린다. 밑줄·취소선은 런 구간(끝 공백 제외)에 글꼴 치수로 긋는다.
  - 링크는 파란색에 밑줄이다. Ctrl+클릭으로 열기는 아직 없다.
  - 첨자: 위 −0.33em, **아래 +0.2em**. 설계는 ±0.33em이었지만 아래 첨자가 너무 내려가 줄 아래로 나가므로 바꿨다.
- **편집기**:
  - `setMark`, `toggleMark`, `toggleScript`, `clearMarks`, `selectionMarks`(섞임 포함).
  - 단축키: Ctrl+B·I·U, Ctrl+Shift+X, Ctrl+. (위 첨자), Ctrl+, (아래 첨자), Ctrl+\\.
  - 선택 없이 서식을 바꾸면 보류 서식이 되어 다음 입력에 쓰인다. 조합 중 글자도 그 서식으로 보인다. 캐럿이 다른 데로 가면 버린다.
  - 접근성 미러는 굵게·기울임을 `strong`·`em`으로 낸다.

| 입력 예산 (`bench-engine`) | 서식 없는 10만 문단 p50 0.20 / p95 0.32 ms (전과 같은 수준). 서식 많은 10만 문단(문단마다 굵게·크기·기울임·색) p50 0.31 / p95 0.47 / 최대 2.5 ms. 목표 p95 16 ms |

### 남은 것

- 한글 조합 중 보류 서식이 실제 IME에서 굵게 보이는지는 체크리스트 `v1-bold-ime`으로 사람이 확인한다.
- 다른 굵기(Medium·SemiBold 등)와 글꼴 이름(`font`, O-19)은 아직 없다. 굵게는 Bold 하나다.
- 링크 열기(`onOpenLink`), 서식 있는 붙여넣기(§5)는 이후 단계에서 한다.
