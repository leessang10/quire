# ADR-0001: contenteditable 대신 캔버스 렌더링과 자체 레이아웃 엔진

- 상태: 채택
- 날짜: 2026-11-16

## 배경

해결 대상 9가지(00 §1) 중 L1(페이지 레이아웃), L2(어울림 배치), L3(IME 제어), L5(초대형 문서), L9(정밀 조판)는
`contenteditable`과 브라우저 DOM 레이아웃을 쓰는 한 해결할 수 없다.

## 결정

- 편집 영역에 `contenteditable`을 쓰지 않는다.
- 텍스트 측정, 줄바꿈, 쪽 조립을 자체 레이아웃 엔진이 수행한다.
- 결과를 캔버스에 그린다. 입력은 숨긴 입력 요소 / EditContext로 받는다.
- 접근성, 찾기, 맞춤법, 클립보드는 직접 구현한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| ProseMirror·Lexical 등 위에 확장 | L1, L2, L5, L9가 구조적으로 불가능 |
| DOM 렌더링 + 자체 입력 처리 (DOM에 절대 위치로 글자 배치) | 쪽 조판은 가능하나 DOM 노드 수가 L5를 막고, 브라우저 텍스트 렌더러 의존이 L9·결정성을 막음 |

## 결과

- 얻는 것: 조판, 입력, 성능을 완전히 통제
- 잃는 것: 브라우저가 공짜로 주던 접근성, 찾기, 맞춤법, 번역, 텍스트 선택 기능 → 04에서 대체
- 위험: 입력 호환성과 접근성 → 0단계에서 먼저 검증
