# ADR-0003: CRDT 구현 선택

- 상태: 채택 (구획 순서의 세부 의미론은 4단계 과제)
- 날짜: 2026-11-16
- 근거: [0단계 V4 결과](../spikes/phase0-crdt.md)

## 배경

협업(L8), 변경 추적(L6), 겹치는 범위(L7)를 위해 문서 모델을 CRDT 위에 둔다.
핵심 난제는 블록 이동과 문단 분할·병합을 동시에 안전하게 지원하는 것이다 (05 §3).

## 검토한 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| Yjs | 성숙, 생태계 큼 | 이동 연산 없음 |
| Loro | 이동 가능한 리스트·트리, 서식 텍스트(Peritext 계열), 버전·실행 취소 내장 | 상대적으로 신생, 텍스트 구간 이동은 미지원 |
| 자체 구현 | 원하는 의미론을 정확히 구현 | 개발·검증 비용 매우 큼 |

Loro 위에서 두 가지 문서 표현을 비교했다.

| | M1 평평한 텍스트 + ¶ | M2 이동 가능한 문단 리스트 |
|---|---|---|
| 의도 시나리오 18개 | 통과 12, **유실 0**, 중복 1 | 통과 7, 유실 3, 중복 4 |
| 실패 유형 | 문단 이동·삭제와 겹친 편집이 원래 자리에 남음 | 분할·병합과 겹친 입력이 사라지거나 복제됨 |
| 1만 쪽 문서 만들기 / 스냅샷 | 272 ms / 1.3 MB | 63.6 s / 11.9 MB |
| 업데이트 1회 고정 비용 (1만 쪽) | 약 16 ms (묶으면 해결) | 0.05 ms |

## 결정

1. CRDT 구현은 **Loro**를 쓴다. 편집기 코드는 `@quiredoc/sync` 어댑터를 통해서만 접근한다 (교체 가능성 유지).
2. 스토리 표현은 **M1: 스토리마다 `LoroText` 하나, 문단 끝은 ¶ 문자**로 한다 (01 §2와 동일).
3. 스토리 끝에는 화면에 나오지 않는 **보초 구획** `[구획 표식, ¶]`을 둔다. 스토리가 ¶로 끝난다는 조건은 보초가 지키므로, 사용자 문단 삭제는 예외 없이 숨김이다. 보이는 문단이 없으면 미리 만들어 둔 **자리표시 문단**(텍스트 순서상 첫 것)을 빈 문단으로 보여 주고, 입력하면 사용됨으로 표시한다(두 피어가 동시에 입력해도 같은 문단) (M1의 "앞 문단 ¶를 대신 지우는" 예외는 동시 편집 중 구획 경계와 만나 빈 문단을 남겼음, [후속 4](../spikes/phase0-crdt.md#후속-4-s25와-보초-구획)).
4. 문단 이동은 **구획 순서 방식**으로 한다 (연달아 붙은 구획 표식을 한 구획으로 묶는 별칭 규칙은 두지 않는다, [후속 5](../spikes/phase0-crdt.md#후속-5-빈-구획과-별칭-규칙)): 텍스트 안에 보이지 않는 구획 표식을 두고, 화면 순서는 구획 ID의 이동 가능한 리스트로 정한다. 이동은 글자를 옮기지 않고 구획 순서만 바꾸므로 동시 편집이 함께 움직인다. 구획 ID는 **구획을 끝내는 표식**으로 정한다(M4): 문단을 떼어 내도 나머지 부분이 원래 ID와 자리를 유지하므로, 서로 다른 문단을 동시에 같은 자리로 옮겨도 양쪽 의도가 보존된다. 0단계 비교에서 시나리오 30개 중 29개 통과, 유실·중복 0 ([후속 결과](../spikes/phase0-crdt.md#후속-2-기준anchor-방식-검토와-m4-끝-표식-구획)).
5. 동기화 계층은 **Worker**에서 실행하고, 업데이트 내보내기·적용을 **50–100 ms 단위로 묶는다.**

## 후속 과제

- 구획 정리: 0단계에서 규칙을 정함 ([후속 3](../spikes/phase0-crdt.md#후속-3-구획-정리-규칙)). 화면 계산은 숨긴 구획을 건너뛴 조각 단위(R1), 숨긴 내용은 실행 취소 기록에서 빠질 때 삭제(R2), BRK 물리 삭제는 편집 중에는 하지 않고 정본 저장·새 판 압축 때만(R3).
- 구획 목록 탐색을 균형 트리로 (지금은 선형. 구획 171개, 10만 문단에서 키 입력 영향 없음, 이동 약 3 ms)
- Loro 텍스트 마크 확장 규칙 확인 (01 O-5)
- 큰 텍스트 컨테이너의 업데이트 고정 비용을 업스트림에 확인
