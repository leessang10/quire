# ADR-0003: CRDT 구현 선택

- 상태: 제안 (0단계 V4 결과로 확정)
- 날짜: 2026-11-16

## 배경

협업(L8), 변경 추적(L6), 겹치는 범위(L7)를 위해 문서 모델을 CRDT 위에 둔다.
핵심 난제는 블록 이동과 문단 분할·병합을 동시에 안전하게 지원하는 것이다 (05 §3).

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| Yjs | 성숙, 생태계 큼 | 이동 연산 없음 → 이동 시 유실·복제 (L8 미해결) |
| Loro | 이동 가능한 리스트·트리, 서식 텍스트(Peritext 계열) 내장, 버전·체크아웃 지원 | 상대적으로 신생, 텍스트 구간 이동은 미지원 |
| 자체 구현 | 01의 평평한 열 + 구간 이동 의미론을 정확히 구현 | 개발·검증 비용 매우 큼 |

## 제안

- `@quire/sync` 어댑터 뒤에 CRDT를 숨긴다 (교체 가능성 확보).
- 0단계에서 다음 두 조합을 시나리오 테스트(05 §7)로 비교한다.
  - Loro 텍스트(평평한 열) + 이동 포워딩 (M1)
  - Loro MovableList(블록) + 블록별 텍스트 (M2)
- 두 안 모두 핵심 시나리오를 통과하지 못하면 자체 구현(M3)을 검토한다.
