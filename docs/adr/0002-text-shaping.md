# ADR-0002: 텍스트 셰이핑 방식

- 상태: 채택 (2026-11-17, [셰이핑 검증](../spikes/phase0-shaping.md))
- 날짜: 2026-11-16

## 배경

레이아웃 결정성(02 R1)과 정확한 캐럿 위치를 위해 글리프 단위 위치가 필요하다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| Canvas `measureText` | 구현 간단, 추가 의존성 없음 | 글리프별 위치·클러스터 정보 없음, 브라우저·OS별 결과 차이 → 결정성 불가 |
| HarfBuzz (WASM) | 글리프 ID·위치·클러스터 매핑, 모든 환경에서 같은 결과 | WASM 용량(수백 KB), 글꼴 파일 직접 관리 필요 |

## 제안

- 0단계: `measureText`로 빠르게 시작 (입력·선택 검증이 목적).
- 1단계부터: HarfBuzz로 교체. 레이아웃 엔진은 처음부터 `Shaper` 인터페이스 뒤에 셰이핑을 숨겨 교체 비용을 줄인다.
- 렌더링은 우선 `fillText`를 쓰고, HarfBuzz 결과와 화면 글리프가 어긋나는 문제가 확인되면 글리프 경로 렌더링으로 전환한다 (04 O-12).

## 검증 결과 (2026-11-17)

[0단계 셰이핑 검증](../spikes/phase0-shaping.md)으로 제안을 확정한다.

- **결정성**: 같은 WASM·같은 글꼴 파일이면 Node와 브라우저의 HarfBuzz 결과가 정수까지 같다 (지문 일치).
- **캔버스와 같은 폭**: 같은 글꼴 파일을 `FontFace`로 넣은 캔버스 `measureText`는 글자별·커닝 런 모두 HarfBuzz와 0.000 px까지 같다. 그래서 **렌더링은 `fillText`를 유지한다** (글리프 경로 렌더링으로 바꾸지 않음, 04 O-12 해소).
- **한글**: 옛한글을 포함해 클러스터 = grapheme. 캐럿 단위와 그대로 맞는다.
- **비용**: `harfbuzz.wasm` gzip 180 KB. 글자별 측정 방식의 조판은 캔버스보다 빠르고(1만 문단 304 vs 371 ms), 문단 통째 셰이핑은 캔버스 측정과 비슷하게 비싸다(140 µs/문단).

## 결정

- 1단계에서 `Measurer`를 셰이퍼 인터페이스로 바꾸고 HarfBuzz(harfbuzzjs)를 넣는다.
- 글꼴은 엔진이 불러온 파일만 쓴다. 렌더러도 같은 파일을 `FontFace`로 쓴다 (시스템 글꼴 이름 금지).
- 셰이핑 앞에 아이템화(스크립트별 런, 엔진이 불러온 대체 글꼴)를 둔다. 맑은 고딕에 없는 이모지·결합 문자에서 캔버스와 갈렸다.
- 셰이핑 단위는 어절 + 캐시로 시작한다 (문단 통째는 10만 문단에서 14초).
- 줄을 `fillText` 한 번으로 그리려면 위치도 같은 런을 커닝·합자를 켜고 셰이핑한 값이어야 한다. 지금의 "글자별 폭 + 줄 단위 그리기"는 합자 글꼴에서 캐럿이 어긋난다 (캔버스는 합자를 끌 수 없음).
